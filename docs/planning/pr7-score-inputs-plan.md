## 1. 범위와 완료 조건

- 기존 적재 데이터를 이용하는 `public.score_inputs(lat, lng, radius_m, floor)`를 추가한다. 반환은 항상 `demand`, `flow`, `transit`, `market`, `compete`, `building`, `rent`, `meta`의 8개 최상위 키다.
- S1 데이터 적재는 완료 상태로 취급한다. 이번 범위는 조회 계약 통합·정합성·권한·성능 검증이며 신규 원천 수집, 원격 Supabase 전환, 채점·UI는 포함하지 않는다.
- 고정 좌표 3곳 × 반경 500m/1km × 층 2의 **6개 조합 각각 30회**, DB 실행 시간 p95 < 1,000ms가 완료 조건이다. HTTP 왕복도 별도로 기록한다.
- 임대동향 공간 연결은 PR 6의 비활성 상태를 유지한다. 공식 공간 적용 근거가 없는 `rent_level=NULL`은 정상 결측이며, S1 통과를 위해 임의 값으로 채우지 않는다.

## 2. RPC 구성과 다대다 증폭 방지

입력 검증 → 공통 좌표·반경 도형 → 소스별 후보 추출 → 묶음별 한 행 집계 → 한 행끼리 결합 → JSON 반환 순서로 구성한다.

- 입력 좌표·반경·층의 NULL/범위/형식을 검증한다. 위경도 인자는 이름으로 호출하고 `ST_MakePoint(lng,lat)` 순서를 고정한다. 지상/지하층을 구분하고 지상 2층을 다른 층으로 대체하지 않는다.
- 공통 입력은 EPSG:4326 점, geography 점, EPSG:5186 점·반경 원 및 인덱스 검색용 4326 경계다. 면적 비율 계산은 5186, 거리 기반 검색은 기존 geography 인덱스를 사용한다.
- 원천 행들을 서로 직접 조인하지 않는다. 학교·상가·학원은 각자 집계하고, 교통은 정류장별 시간 집계 후 반경 집계, 생활인구는 셀→요일·시간→묶음 순서로 집계한다.
- 모든 최종 묶음 CTE는 빈 데이터에서도 정확히 한 행을 만든다. 소그룹 GROUP BY 결과는 JSON 집계 또는 조건부 집계로 다시 한 행으로 접는다. 마지막에는 이 한 행들만 CROSS JOIN한다.
- DISTINCT를 마지막에 붙여 잘못된 곱집합을 숨기지 않는다. 건물과 대장의 1:N 관계는 고유 건물/대장 키로 단계별로 처리한다.
- 기존 반경 SQL 파일을 이어 붙이거나 여러 RPC를 HTTP로 호출해 합치지 않는다. 기존 의미·필터·단위만 보존하며 통합 SQL 안에서 집계 단위를 다시 구성한다.
- 반복 사용되는 후보 집합만 실행계획에 따라 MATERIALIZED 여부를 결정한다. CTE가 있다는 사실만으로 단일 스캔·최적화를 가정하지 않는다.

## 3. 묶음별 데이터 계약

| 묶음 | 집계 및 보존 규칙 |
| --- | --- |
| demand | 행정동과 반경 원의 교차 면적 비율로 주민등록 5~9·10~14·15~18세를 배분한다. 학교 elem/mid/high는 요청 반경 내 별도 집계 후 결합한다. 주민등록 추정과 학교 실개수를 구분한다. |
| flow | 250m 격자 교차 면적 비율로 시간별 생활인구를 합산한다. weekday/weekend 각각 0~23시 고정 24칸과 [15:00,22:00) 7시간 평균을 반환한다. 원천의 유효일 평균·sample_days 의미를 유지하고 재차 날짜 평균을 내지 않는다. 생활인구 15~19세를 15~18세로 분할하지 않는다. |
| transit | 최근접 지하철역은 최대 2,000m, 버스정류장 개수와 지하철 골든타임 승하차는 요청 반경이다. 정류장별 7개 시간·승하차 값의 완전성을 확인한다. 교통은 요일 구분 없는 일평균이며 신분당선을 보정하지 않는다. |
| market | 반경 내 상가 총수와 대분류별 개수. 완료된 서울 스냅샷에서 대상이 없으면 0/빈 map, 미적재 또는 범위 밖은 NULL과 사유다. |
| compete | 반경 내 개원 학원·교습소 총수와 원천 분야별 개수. 국어·논술 등 새 과목 분류는 하지 않는다. 지오코딩 실패는 관측 한계로 반환한다. |
| building | 후보 점을 포함하는 유일한 footprint와 요청 층의 원천 사실. 아래 후보 건물 규칙을 따른다. 반경 전체 건물 목록이나 반경 평균을 후보 건물 값으로 사용하지 않는다. |
| rent | 후보 법정동·요청 층의 일반/집합 분리 집계, 다수 표본 유형·표본수·5건 미만 단가 NULL을 유지한다. 임대는 포함 상권→검증된 공식 권역→NULL, 유형 혼합·근접 상권·과거 분기 대체 금지다. |

결측을 SUM/AVG가 조용히 제외하지 않도록 유효성 개수와 기대 개수를 함께 확인한다. 공간 범위에서 필요한 셀·시간/연령 값이 없으면 해당 완전 집계값은 NULL과 결측 사유를 반환한다. 골든타임 7시간 중 결측이 있으면 유효 시간만의 평균으로 바꾸지 않는다. 원천 PR 2의 '유효 날짜만으로 계산한 셀 평균' 정책은 유지하며, 공간 집계 결측을 새 인구 추정으로 메우지 않는다.

후보 건물 규칙:

- ST_Covers로 포함 도형을 찾는다. 0개는 미매칭, 복수는 모호한 매칭으로 기록하고 후보 단일값은 NULL로 둔다. 최근접 건물이나 같은 PNU의 임의 대장을 선택하지 않는다.
- 높이·층수는 선택 footprint의 기존 확정 필드를 사용한다. unknown 높이는 NULL이며 표시/차폐용 4m를 실제 높이에 대입하지 않는다.
- 표제부는 기존 PK·PNU 검증 연결만 사용한다. WFS 보조 도형은 높이 등의 원천 사실만 제공하고 대장 미연결 값을 채우지 않는다.
- 요청 층은 층 구분 코드와 번호를 함께 매칭한다. 같은 층의 여러 용도는 `floor_use` 배열에 코드·원문·면적·주부속 구분을 보존하고 하나로 임의 선택하지 않는다. 승강기는 승용/비상용 원천 개수를 구분한다. 이 세부 JSON 타입을 data-sources.md에 먼저 확정한다.
- 반경 내 unknown 높이 비율은 후보 건물 값과 별도 계산한다. SHP와 WFS를 포함한 고유 footprint 수가 분모이며, 0개이면 비율은 NULL이다.

## 4. meta와 권한

제안 계약:

```text
meta.radius_m, meta.floor, meta.computed_at
meta.sources.<source>:
  source_version, reference_date 또는 period_start/period_end/quarter,
  ingested_at, coverage, availability, 결측·부분관측 사유
meta.estimated_fields: [{path, reason, method}]
meta.missing_fields: [{path, reason, source}]
meta.height_quality:
  radius_m, total_buildings, unknown_buildings, unknown_ratio
```

- sources는 묶음별 하나의 날짜로 뭉개지 않는다. 행정동 경계/주민등록, 격자/생활인구, 지하철/버스 위치와 승하차, 상가/학원/학교, SHP/WFS/표제부/층별개요, 법정동/실거래/R-ONE을 구분한다.
- 예: 주민등록 2026-08, 생활인구·교통 집계 2026-06~08, 실거래 2024-09~2026-08, 임대동향 2026Q2. 실제 값은 적재된 출처·스냅샷에서 읽고 코드에 고정하지 않는다. 조회일을 원천 기준일로 위장하지 않으며 미확인 기준일은 NULL과 사유다.
- estimated_fields는 실제 추정된 반환 필드의 경로와 승인된 면적 비례/높이 추정 근거를 나열한다. missing_fields는 반환 NULL과 원천 부분관측을 구분해 설명한다. 목록 순서는 고정해 재현 가능하게 한다.
- height_quality의 범위는 요청 반경이다. 같은 반경의 buildings_in_radius 집계와 비교하며 unknown_ratio = unknown_buildings / total_buildings를 확인한다.
- score_inputs는 STABLE·SECURITY INVOKER로 두고 기존 공개 원천 SELECT RLS를 유지한다. anon/authenticated에는 조회 실행만 허용한다.
- 기존 place_snapshots/transit_coverage/building_snapshots/rent_snapshots/ingest_runs는 비공개다. 이 테이블을 공개하거나 전체 감사 JSON을 노출하지 않는다. 필요하면 고정 쿼리·빈 search_path·허용 컬럼만 반환하는 최소 SECURITY DEFINER 메타데이터 함수를 만들고, 소스 정보만 반환하도록 권한·응답 검사를 둔다. 동적 SQL·사용자 데이터 접근은 없다.
- 조회 때 40만 행 등의 기준일을 매번 전수 집계하지 않도록 기존 스냅샷 메타데이터를 우선 활용한다. 날짜·적재 상태가 증명되지 않으면 임의 기본값을 만들지 않는다.

## 5. 기존 RPC/SQL 병존 판단

| 기존 경로 | PR 7 판단 |

임대 조회 규칙은 권한이 제한된 한 행 반환 SQL helper로 추출해 rent_inputs와 score_inputs에서 공유하는 안을 우선한다. helper도 내부에서 먼저 집계하며, 출력은 한 행이어야 한다. 기존 rent_inputs 전체 결과 회귀 테스트를 통과시킨다. 공개 RPC를 제거하거나 과거 마이그레이션을 수정하지 않는다.

| 한티 | 127.052873, 37.496237 | 500 / 1,000m | 2 |

한티 좌표의 법정동은 도곡동이라는 PR 6 결과를 유지한다. 실제 좌표가 건물 밖이어도 옮기지 않으며 building NULL과 사유를 검증한다. 건물·층의 양수 값 동작은 별도 fixture와 적재된 건물의 검증점으로 보완하되 6조합 성능 결과에 섞지 않는다.

1. 승인 범위의 실제 테이블 행수·스냅샷·기준일과 소스 적재 완료 상태를 기록한다. 통합 전후 기존 행수 및 핵심 집계를 비교한다. 로컬 DB 환경·버전·설정·용량을 기록하며 추가 VACUUM·원격 전환을 하지 않는다.
2. 각 묶음을 독립 소스 집계/이전 검증 결과와 전수 필드 비교한다. 인구·생활인구는 단순한 독립 면적 교차 계산과 대조한다. float 값은 명시한 허용 오차, DECIMAL·개수·NULL은 정확 비교한다.
3. 다중 학교×상가×학원, 건물×층별개요, 역×시간대 fixture로 타 소스 행 추가가 무관한 묶음의 합계에 영향을 주지 않는지 확인한다. 모든 중간 최종 묶음 행수=1, 최종 결과 행수=1을 검증한다.
4. 미적재/적재 후 0개/범위 밖/부분 결측, 인구 비공개, weekday/weekend와 24시간 순서, 교통 7시간 누락, 층 없음·지하층·복수 건물, 법정동 모호함, 실거래 최소 5건, 임대 미검증 및 최신 분기 결측을 검증한다. 추정·결측 목록과 실제 payload가 일치해야 한다.
5. anon/authenticated 조회와 관리자 기준 결과를 대조한다. 쓰기·비공개 메타데이터 직접 조회·다른 사용자 개인 데이터 접근은 계속 차단됨을 검사한다.
6. 6개 조합별 준비 호출 3회를 제외하고 30회 측정한다(총 유효 DB 측정 180회). `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)`의 Execution Time으로 p95를 계산한다. 기존 verifier와 같은 nearest-rank 방식, 정렬한 30개 중 29번째 값이다. 조합들을 합쳐 한 p95로 판정하지 않는다.
7. PL/pgSQL 외부 호출 계획만으로 내부 스캔을 판정하지 않는다. 중첩 실행계획 또는 **동일 통합 함수 본문의 집계 SQL**을 추출해 같은 인자로 EXPLAIN ANALYZE한다. 후자는 실제 RPC 결과와 동등함도 확인한다. 인덱스 사용, actual rows/loops, 조인 전후 행수, buffers, 정렬·해시 spill 및 추정 행수 차이를 기록한다.
8. 40만 행 생활인구·55만 행 상가 같은 대형 테이블의 불필요한 전체 스캔, 행별 반복 공간 계산, 조인 증폭을 수정한다. 작은 경계/메타데이터 테이블의 합리적 Seq Scan은 근거를 남기며 무조건 인덱스를 강제하지 않는다.
9. HTTP는 동일 6조합을 각 30회 별도 측정하고 응답을 DB와 비교한다. computed_at 등 동적 시각 필드만 비교에서 제외한다. HTTP p50/p95/max·응답 크기는 기록하며 DB 완료 기준과 혼동하지 않는다. 실제 권한 역할 및 연결 재사용 조건도 기록한다.
10. `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm test:db`를 통과하고, 6개 조합 모두 DB p95 < 1,000ms인지 판정한다. 위 측정은 캐시가 준비된 조건이며 cold 성능으로 표현하지 않는다.

## 8. 리스크와 최종 인계

- 공간 변환/면적 교차와 큰 집계가 주요 성능 리스크다. GiST 선필터·후보 PK 조회·공통 도형 재사용을 적용하고, 구조/해상도 축소 대신 실행계획을 개선한다.
- 원천 NULL과 데이터 부재를 0으로 혼동하거나 부분 합계를 완전한 값으로 표시하는 것이 주요 정합성 리스크다. payload와 메타데이터를 함께 검증한다.
- 후보 도형·층 용도의 복수성, 비공개 스냅샷 메타데이터 권한, 기존 rent_inputs와의 규칙 분기가 추가 리스크다. 임의 매칭 없이 결측 처리하고 공통 조회 규칙과 회귀 검증으로 관리한다.
- 승인된 의미와 실제 데이터가 충돌하면 해당 규칙 변경 전 사용자에게 보고한다. 임대 공간 연결 미활성은 알려진 상태이며 이번 PR에서 해소했다고 표시하지 않는다.
- 모든 판정 통과 후에만 S1 완료로 갱신한다. PR 끝에 (a) S1 완료 기준 체크리스트, (b) 이번 통합 RPC 실제 응답에 따른 문서 수정과 외부 API 재검증 여부, (c) S2 예고를 붙인다.
- 다음 작업은 S2 채점 명세 확정과 서울 전체 건축물 적재의 별도 계획이다. scoring-spec.md 없이 채점 로직을 구현하지 않는다.

## 구현·검증 완료 (2026-09-21)

사용자 지시로 재개해 먼저 `supabase migration list --local`로 두 적용 이력을 확인했다. 기존 마이그레이션을 수정하지 않고 통합·권한·부분 결측 테스트와 검증 스크립트를 완성했다. 실제 6조합 DB p95 12.631~74.117ms, HTTP 별도 30회, 내부 SQL EXPLAIN·독립 집계 대조 통과. 확정 JSON 전체 스키마/실제 응답과 `meta.bundle_ms` 의미는 data-sources.md 3절에 기록했다.

최종 구현은 한 SQL 문장 안의 거대한 CROSS JOIN 대신 한 RPC의 같은 문장 스냅샷에서 각 내부 함수를 한 행으로 집계하고 JSON으로 결합한다. 이 방식으로 묶음별 시간을 직접 계측하며 다대다 증폭을 막는다. `auto_explain` 로딩은 로컬 Supabase에서 거부되어 저장 함수 본문 추출·결과 동등성 대조로 내부 계획을 확인했다. 전체 필수 검사·DB 테스트 및 보완 실제 건물 검증을 포함한 근거는 [PR 7 검증](../validation/pr7-score-inputs-20260921.md)을 따른다. 원격 반영·채점·UI는 하지 않았다.
