# PR 5 — 강남구 건물 footprint·건축물대장·층별개요 계획

작성일: 2026-09-20. 사용자 승인된 구현 계획이다. 기준은 PR 4/GitHub #7이 머지된 `main`(`5b8e095`), 작업 브랜치는 `s1/강남구-건물`이다. 2026-09-20 사용자 수정 승인에 따라 SHP 주 소스·WFS 보조와 높이/unknown 계약을 구현한다.

## 확정된 범위와 용량 정책

- 강남구 전체의 건물 도형·표제부·층별개요를 적재한다. 서울 전체 건물은 S2 초반 별도 태스크다.
- 로컬 DB 500MB 제한은 없다. 원격은 S1까지 무료 플랜을 유지하고, S2 서울 전체 건물 적재 시 Pro 전환을 검토한다.
- 용량은 DB 전체·테이블·인덱스·원본·임시 공간을 구분해 실측만 기록한다. 용량을 이유로 구조·필드·해상도·적재 범위를 바꾸지 않는다. 원격 한도 접근 시 현황을 보고하고 자동 축소나 요금제 변경은 하지 않는다.
- 학원 등록 가능성, 과목 분류, 점수와 층 선호는 S2다. S1은 원천 사실과 문서에 승인된 높이 추정만 제공한다.

## 소스 비교 방법과 현재 증거

강남구 전체 범위 조회까지 완료했다. SHP는 `A23=11680`, WFS는 강남구 경계와 SHP 도형 범위를 포함하는 bbox를 분할 조회한 뒤 `col_adm_se=11680`으로 골랐다. OSM은 기존 강남구 행정동 경계 합집합 안에 도형 내부 대표점이 있는 건물을 셌다. 관할 속성과 공간 판정은 경계에서 차이가 있으므로 동일 판정이라고 표현하지 않는다.

| 소스 | 강남구 원천 도형/행 | 일반·산 PNU로 API 변환 가능 | 양수 원천 높이 | 양수 지상층수 |
|---|---:|---:|---:|---:|
| GIS건물통합정보 SHP | 28,228 | 28,228 (100%) | 16,653 (58.99%) | 22,241 (78.79%) |
| Vworld WFS | 33,345 | 33,343 (99.994%) | 16,655 (49.95%) | 27,122 (81.34%) |
| OSM | 17,263 | 직접 PNU 태그 0 | 2,044 (11.84%) | 3,410 (19.75%) |

WFS는 말단 영역 178개, 전체 237개 요청으로 응답 잘림 없이 읽고 중첩 영역의 feature ID를 중복 제거했다. 전체 bbox의 고유 73,141개가 첫 요청의 numberMatched=73,141과 일치한 뒤 강남구를 골랐다. SHP의 고유 GIS ID **28,227개가 WFS에 모두 존재**하며 WFS에만 있는 일반 GIS ID 2개와 `ufid=NN` 5,115개가 추가된다. NN 5,115개는 PNU·건물관리번호를 모두 보유하고 4,879개는 양수 층수가 있지만 높이·대장 PK는 없다. 나머지 추가 2개는 토지구분이 `6`인 PNU로, API 일반/산 변환을 하지 않고 미확정 사유를 남긴다. PNU 보유율과 실제 표제부 연결률을 구분한다.

SHP와 WFS에는 각각 원천 ID만 다른 동일 도형·업무 속성 1쌍이 있다. 원문 보존 후 정규화 시 1건으로 처리하는 안이다. WFS의 유효하지 않은 geometry는 1건이며 승인 후 수리 전후 검증한다. OSM은 way 17,237개·relation 26개이고, relation에 속한 way를 중복으로 세지 않았음을 확인했다. 강남구 경계로 동일하게 공간 판정하면 SHP 28,202행, WFS 33,316개다. 숫자를 서울 전체 건물 수나 건물 정답 대비 재현율로 해석하지 않는다. [전수 비교·품질 증거](../validation/pr5-footprints-20260920.md)를 따른다.

### 대치동 대장 연결 표본

공통 표본은 대치동 학원가의 EPSG:4326 bbox **(127.059, 37.495)~(127.063, 37.499)**, 약 157,031㎡다. 도형이 이 영역과 교차하는 건물을 센다. 전체 강남구의 품질을 이 표본만으로 단정하지 않는다. 측정일은 2026-09-20이다.

- 도형 수: 원천 식별자와 중복 geometry, 유효성을 확인한다. 건축물대장 행 수와 도형 수는 구분한다.
- PNU 보유율: 전체 도형 중 유효한 19자리 PNU를 가진 비율이다. PNU 유일 개수도 별도로 적는다.
- PNU 대장 연결률: 같은 PNU의 표제부가 1건 이상 조회되는 도형/전체 도형이다. 이것만으로 특정 건물과 표제부의 일대일 연결이 확정되지는 않는다. API 오류는 “대장 없음”에 포함하지 않는다.
- 높이 보유율: 원천에 양수 높이가 있는 비율이다. 층수 보유율과 층수 기반 추정 가능 비율은 별도로 적는다. 높이 0·공백·NULL을 실측 높이로 취급하지 않는다.

| 소스 | 동일 표본 도형 | PNU 보유 | PNU로 표제부 조회 | 원천 높이 | 양수 지상층수 |
|---|---:|---:|---:|---:|---:|
| GIS건물통합정보 SHP | 103 | 103/103 (100%), 66개 PNU | 85/103 (82.52%); 없음 17, API 오류 1 | 38/103 (36.89%) | 88/103 (85.44%) |
| Vworld WFS | 129 | 129/129 (100%), 74개 PNU | 108/129 (83.72%); 없음 19, API 오류 2 | 38/129 (29.46%) | 110/129 (85.27%) |
| OSM | 87 | 0/87 | PNU 직접 연결 0/87; 공간/주소 추정 연결은 미실시 | 15/87 (17.24%) | 25/87 (28.74%) |

WFS 129개는 식별자·geometry가 각각 고유하고 모두 유효한 MultiPolygon이며 bbox와 교차한다. `numberMatched=numberReturned=129`로 이 요청의 잘림은 없다. OSM은 닫힌 way 87개이며 원문 태그에 PNU가 없다. 두 소스의 도형 수 차이가 곧 지상 건물 정답 대비 누락률을 뜻하지는 않는다.

WFS 높이 또는 층수가 있는 도형은 110개, OSM은 25개다. WFS 주용도 코드는 88개, 대장 PK는 87개에 있으나 **공식 변환 전의 구 PK를 현행 건축HUB PK와 직접 비교하면 일치한 도형은 0개**다. 아래의 공식 PK 변환 후 같은 PNU 안에서 70개가 연결됐다. PNU만 같은 다건 표제부를 임의로 하나 선택하지 않는다.

### GIS건물통합정보 SHP — 실제 파일 확인 완료

- 사용자 제공 `.local/downloads/AL_D010_11_20260909.zip`은 서울 전체분(135,736,236 byte, DBF 695,754행)이다. **압축을 풀지 않고** ZIP 내부를 직접 읽었다. 강남구는 `A23='11680'`으로 추출했으며 법정동/PNU의 지역 코드도 모두 일치했다.
- `.prj`에 **EPSG:5186**이 명시돼 있다. 강남구 행의 문자 속성은 CP949로 전수 해석했다. 실제 A0~A28의 **29컬럼**은 공식 컬럼 정의서와 대조했다. [전체 컬럼·읽기 방식·해시·검증 기록](../validation/pr5-footprints-20260920.md)을 따른다.
- 강남구 원천 **28,228행**, PNU 유효 **100%**, 고유 PNU **21,753개**, 양수 지상층수 **22,241행(78.79%)**, 원천 높이 **16,653행(58.99%)**, 주용도 코드 **22,302행(79.01%)**다. 지상층수 0/NULL은 5,978/9행, 높이 0/NULL은 11,568/7행이다.
- A0만 다른 완전 중복 1쌍을 확인했다. 나머지 업무 속성·GIS ID·geometry가 모두 같으므로 원문은 R2에 보존하고 정규화에서는 1건만 유지하는 안이다(28,227개). 서로 다른 속성의 동일 GIS ID를 임의로 합치지 않는다.
- ring self-intersection 도형 4개는 읽기 전용 `ST_MakeValid` 진단에서 Polygon과 면적을 유지했다. 승인 후 면적·bbox·유효성을 확인하고 이 조건을 통과한 도형만 수리하며 `geometry_repaired`와 원문 WKB를 보존한다. 수리로 면적/범위/차원이 바뀌면 적재 전에 보고한다.
- 배포 기준일은 2026-09-09, 모든 행의 A22 기준일은 2026-09-06이다. A28 생성변경일과 적재일을 별도로 보존한다.
- SHP 103개와 WFS의 유효 GIS ID 103개는 같은 집합이다. WFS 추가 26개는 `ufid=NN`, 높이 0·대장 PK NULL이며 22개에는 층수가 있다. 이 차이를 보고하되 정답 대비 누락률로 단정하거나 이번 PR에서 자동 합치지 않는다.
- 운영은 **수동 다운로드 후 R2 raw/에 게시, 갱신 주기 분기**다. 서울 전체 원본을 보존하고 S1 조회 DB에는 강남구만 적재한다. 사용자가 ZIP을 제공하면 검사 후 전체 원문 속성/원천 geometry를 Parquet로 게시하고 ZIP 해시·PRJ·공식 정의서를 기록한다. 새 파일 없이 source_version을 갱신하지 않는다. 이번 조사에서는 게시하지 않았다.

### 이용조건

- **SHP**: 배포 화면은 `CC BY`를 표시하지만 “CCL라이센스 바로가기”는 `BY-NC-ND 2.0 KR`로 연결되는 불일치가 있다. 파일에는 별도 라이선스 문서가 없으므로 제공기관의 원천 라이선스를 확인해 상업 이용·가공·R2 보관·재배포 적용 조건을 확정해야 한다. 화면 문구만으로 모든 이용이 허용됐다고 단정하지 않는다.
- **WFS**: [GIS건물통합정보 데이터셋 명세](https://www.data.go.kr/catalog/15123970/openapi.json)는 이용허락범위 제한 없음을 표시한다. 별도로 [Vworld 약관](https://www.vworld.kr/v4po_prcint_a001.do) 제13조에는 영리 목적 서비스 이용에 운영기관 동의가 필요하며, 제19조에는 정보 복제·가공·타인 제공의 승낙 조건이 있다. API 인증 성공은 이 이용조건이 해결됐다는 뜻이 아니다. 선택 전 길목의 배치 보관·서비스 제공에 적용되는 동의/허용 범위를 확인한다.
- **OSM**: [ODbL](https://www.openstreetmap.org/copyright)과 [표시 지침](https://osmfoundation.org/wiki/Licence/Attribution_Guidelines)을 따른다. 상업 이용은 가능하지만 출처/라이선스 표시와 공개 파생 DB의 공유 조건을 고려해야 한다. 다른 원천과 결합한 DB가 파생 DB에 해당하는지 확인 없이 제한 없는 원천과 같은 방식으로 재배포하지 않는다.
- **도로명주소**: 사용자는 미신청 상태다. 건물DB TXT는 도형 자료가 아니며 별도 건물 도형·전자지도는 제공 신청 경로다. 위 세 소스가 모두 부족할 때만 신청을 제안한다.

### 확정 소스와 선택 근거

**SHP를 주 소스로 확정한다.** 사용자 결정의 근거는 강남구 PNU 100%, 표본의 대장 연결률 우위, CC BY 배포 조건, 주 데이터 확보 시 API 약관·쿼터에 의존하지 않는 수동 파일 스냅샷이다. 이전 WFS 주 소스 추천은 이 결정으로 대체한다. 사용자 결정과 포털/실파일 실측은 구분해 기록한다.

WFS는 SHP에 없는 도형만 보조로 추가하고 `source`를 구분한다. 보조 도형의 대장은 연결하지 않으며 건물 적합성·용도·승강기 등 대장 기반 집계에서 제외한다. **WFS도 3D 표시와 가시성 차폐 계산에는 포함하며 SHP와 같은 높이 규칙을 쓴다.** 동일 GIS ID·동일 도형을 추가하지 않고 실제 겹침 분포를 검증한다. WFS 보조 확보에는 해당 API의 이용조건·쿼터가 적용된다.

SHP 운영은 **수동 다운로드 후 R2 raw/에 게시, 갱신 주기 분기**다. 서울 전체 ZIP 원본을 보존하고 S1 조회 DB에는 강남구만 적재한다. 완전 중복 1쌍은 정규화 시 하나만 남기며 자기 교차 4건은 `ST_MakeValid`로 정리한다. 원본 ZIP·속성·geometry는 R2에 수정 없이 보존하고 수리 여부를 기록한다. 도로명주소 도형 신청은 세 소스가 모두 부족할 때만 제안한다.

## 건축HUB 사전 확인과 연결 원칙

[공식 서비스](https://www.data.go.kr/data/15134735/openapi.do)의 `getBrTitleInfo`, `getBrFlrOulnInfo`를 실제 호출했다.

- WFS 표본의 PNU 74개 중 72개 응답을 확보했다. 표제부가 있는 PNU는 62개, 표제부 180행이다. 10개 PNU는 정상 응답의 totalCount=0이며, 2개 PNU는 HTTP 503이다. 후자를 빈 대장으로 확정하지 않는다.
- PNU는 시군구 5자리·법정동 5자리·토지구분 1자리·본번 4자리·부번 4자리로 분해한다. PNU 일반/산 구분과 API `platGbCd` 값은 다르므로 명시적으로 변환한다. 0 패딩과 문자열 원형을 보존한다.
- 원천 대장 PK는 최대 22자리 정수로 반환됐다. float나 JS number를 거치지 않고 문자열로 보존한다. 공식 첨부 PDF 두 개에서 **22자리 신규 PK는 그대로, 구 일련번호는 강남구 코드 1024 + 실대장 구분 1 + 일련번호**로 변환함을 확인했다. 이 규칙 적용 후 같은 PNU 안에서 SHP 70/103개(67.96%), WFS 70/129개(54.26%)가 현행 표제부 PK까지 정확히 일치했다. 폐말소대장 구분 0은 임의 대입하지 않는다.
- WFS 표본에서 한 PNU에 footprint 1개·표제부 1개인 후보는 46개다. 공식 PK 연결을 우선하며, PK 미보유/불일치 건은 단지·본관/부속·다동을 별도로 확인해야 한다. PNU만으로 여러 도형에 같은 표제부 높이·승강기·층별개요를 복제하지 않는다. 미연결 사유를 보존하고 도형 자체는 남긴다.
- 한 필지의 표제부 1행↔층별개요 12행, 아파트 필지의 표제부 44행↔층별개요 507행을 확인했다. 두 표본에서 층별개요는 표제부 PK로 모두 연결됐다.
- `numOfRows=1000` 요청에도 응답은 100행이다. 아파트 층별개요는 6페이지를 읽어 507행과 totalCount를 대조했다. 페이지의 `rnum`을 안정적인 층 식별자로 취급하지 않는다. 지하·지상·옥탑 구분과 층번호/원문 이름을 보존한다.
- 표제부·층별개요의 모든 원문 필드는 R2 Parquet로 보존한다. 성공 응답을 재사용하고 스냅샷 ID/법정동/대지구분/오퍼레이션/페이지/페이지크기별 수집 상태를 기록한다. PNU별 보완 조회도 별도 캐시한다. 503·타임아웃은 결측으로 처리하지 않으며 제한된 재시도 후 미완료 상태로 중단/재개한다. 계정 잔여 쿼터는 미확인이다. 실제 건수 기반 호출 계획은 다음과 같다.

### 전체 수집 호출 계획

WFS의 일반/산 PNU도 SHP와 같은 조합에 속한다. 번/지를 생략하고 강남구 **14개 법정동·일반/산 21조합**을 조회할 수 있음을 42개 count 응답으로 확인했다. 응답 첫 행의 지역/대지구분 불일치는 0건이다. totalCount 합계는 표제부 **24,324행**, 층별개요 **198,637행**이다. 아직 이 전체 행을 수집한 것은 아니다.

100행 단위 페이지는 표제부 **255회**, 층별개요 **2,000회**, 합계 **약 2,255회**다. SHP 필지별 최소 43,506회 대신 동 단위 페이지 수집을 우선한다. WFS 전수 비교에서 확인한 PNU 23,292개 중 토지구분 6인 2개는 API 변환 대상에서 제외하고 실패 사유를 기록한다. 건축HUB 기본 개발 트래픽 10,000건/일의 22.55%이며 실제 계정 잔량은 별도 확인한다. WFS는 별도 서비스이며 이번 범위에서 237회 요청이 필요했다. WFS 계정 잔여 쿼터는 미확인이다. 수집 중 totalCount 변화/중복/누락을 검증하고 키/쿼터 오류는 중단한다. 503은 빈 대장으로 저장하지 않는다.

## 마이그레이션 설계안

SHP A0/A1/A19·공식 PK 연결과 WFS 보조 feature ID로 DDL을 확정한다. `ufid=NN`을 유일 키로 쓰지 않는다. 데이터 구조 선택 이유는 업무상 의미와 연결 관계이며 저장 용량이 아니다.

- `buildings`: 고유 도형 ID·원천 ID·PNU·MultiPolygon(4326), 원천 높이/층수/주용도, 확정 높이·height_source·height_estimated·표시/차폐 높이, 대장 연결 상태/사유, 공통 출처·기준일·적재일·estimated·geometry_repaired. 미연결 건물도 geometry와 확인된 원천 속성을 유지한다.
- `building_registers`: 현행 대장 PK(text)를 기준으로 PNU, 건물/동 이름, 지상·지하층수, 높이, 용도 코드/원문, 연면적, 승용·비상용 승강기, 사용승인일과 출처를 보존한다.
- `building_floors`: 대장 PK에 연결된 층 구분 코드/원문·층번호/원문·주용도 코드/원문·기타용도·면적·본관/부속 구분. 하나의 층에 여러 용도 행이 올 수 있으므로 `(건물, 층번호)`로 원천 행을 합치지 않는다. 실제 중복 분포를 확인해 행 식별 규칙을 정한다.
- 도형↔대장 연결은 검증된 원천 키 또는 명시적으로 확인한 관계만 저장한다. 일대다/다대다를 단일 FK로 강제하지 않으며 연결 관계가 확인되면 별도 연결 테이블을 둔다. 미확정 연결은 nullable 상태/사유로 남긴다.
- 공간 인덱스와 공개 데이터 SELECT RLS, 배치 전용 쓰기를 설정한다. 원자적 스냅샷 교체·재실행 시 중복 없음·실패 시 이전 데이터 보존을 보장한다.

## 확정 높이·차폐·신뢰도 계약

1. 선택한 도형 원천 높이가 양수이면 그대로 사용한다. 대장 높이를 우선 대입해 덮어쓰지 않는다.
2. 원천 높이가 없고 지상층수가 양수이면 층수×3.3m로 추정한다. 원천 주용도로 확인한 1층 단층 상업건물은 4.0m다. `estimated=true`, `height_estimated=true`와 근거를 남긴다.
3. 높이·층수가 모두 없으면 `height_m=NULL`, `height_source='unknown'`이다. 3D 표시와 차폐 입력에서는 4.0m를 사용하되 이 값을 실제 높이 컬럼에 저장하지 않는다.

SHP와 WFS 보조 모두 차폐 계산 대상이다. 결과 신뢰도에는 해당 차폐 대상 중 unknown 건물 수/전체 건물 수인 `unknown_ratio`를 함께 반환한다(대상이 없으면 NULL). 원천별 건수도 별도로 제공한다. PR 5는 이 데이터/RPC 계약을 검증하고 실제 3D 렌더러·레이캐스트 소비는 S2/S3에서 구현한다. 가시성 점수는 S2 채점 명세 없이 구현하지 않는다.
