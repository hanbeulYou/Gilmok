# PR 6 — 강남구 실거래·임대동향 계획

작성일: 2026-09-20. **사용자 승인·구현 및 실제 적재 검증 완료(2026-09-20)**. 기준 브랜치 `main`, 예정 브랜치 `s1/실거래-임대동향`, PR 설명 첫 줄 `base: main`.

로컬 main의 `8c7c6db`는 GitHub #8 머지 커밋이다. AGENTS.md와 기존 기획서의 PR 5 “리뷰 대기” 표시는 갱신 대상이다. 이번 조사에서는 외부 요청을 `/ingest`에서 실행하고 응답을 gitignore 대상 `.local/validation/pr6/`에만 보관했다. 계획 당시에는 제품 코드·마이그레이션·DB·R2를 변경하지 않았다. 승인 후 결과는 [PR 6 실제 검증](../validation/pr6-rent-20260920.md)에 기록했다.

## 범위와 저장 계약

- 강남구 상업업무용 **매매** 최근 완료 24개월: 2024-09-01~2026-08-31. 계약월 기준이며 2026-09의 진행 중 자료는 제외한다. 완료된 월도 지연신고·해제로 수정될 수 있다.
- 임대동향은 강남구와 연결되는 조사 상권의 최신 공표 분기부터 시작한다. 실제 2026년 2분기 응답을 확인했다. 매매의 24개월 조건을 임대동향에 임의 적용하지 않는다.
- 개별 거래 원본은 R2, Supabase에는 법정동·층별 집계와 조회에 필요한 경계·출처 메타데이터만 저장한다. 원천 임대동향은 이미 조사 상권별 집계이며, 건물유형별로 보존한다.
- 후보 좌표가 속하는 법정동/조사 상권을 조회한다. 매매 통계를 반경 내 거래 통계로 표시하지 않는다. 조사 상권과 좌표 연결이 없거나 모호하면 NULL이다. 근접 상권, 행정동 평균, 서울/강남 권역 평균으로 대신하지 않는다.
- PR 6은 수집·집계·`rent` 조회 검증까지다. 전체 7개 묶음 `score_inputs` 통합과 S1 최종 판정은 다음 태스크다. 점수·유형 선호·사용자 임대료 대체 판단은 구현하지 않는다.

## 사전 확인 결과 — 법정동

`admin_dongs`는 주민등록 인구용 **행정동**이다. 법정동 “대치동”과 행정동 “대치1동/대치2동/대치4동”은 같은 단위가 아니며 코드 직접 조인·이름 유사 매칭을 하지 않는다.

별도 경계 소스로 [국토부/Vworld 행정구역도 WFS](https://www.data.go.kr/data/15059008/openapi.do)의 **`lt_c_ademd_info`**를 실제 조회했다. 강남구 14개 법정동의 `emd_cd`(8자리), `emd_kor_nm`, EPSG:4326 경계가 확인됐고 유효하지 않은 도형은 0개였다. 이번 bbox 응답은 주변 지역 포함 68개이며 코드 `11680`으로 필터링했다. 거래에 나타난 14개 동명은 이 14개 경계명과 일치한다.

역삼동 `11680101`, 개포동 `11680103`, 청담동 `11680104`, 삼성동 `11680105`, 대치동 `11680106`, 신사동 `11680107`, 논현동 `11680108`, 압구정동 `11680110`, 세곡동 `11680111`, 자곡동 `11680112`, 율현동 `11680113`, 일원동 `11680114`, 수서동 `11680115`, 도곡동 `11680118`.

계획은 별도 `legal_dongs` 테이블과 공간 인덱스다. 원천 8자리 코드를 보존하고, 10자리 코드가 필요하면 공식 법정동 코드표와 대조하여 변환 규칙을 검증한다. 도형 기준일·코드 변경 이력·이용조건을 확정한 뒤 적재한다. 경계선상 다중 매칭/미매칭을 임의로 하나 선택하지 않는다. 기존 `admin_dongs`·인구 집계는 변경하지 않는다.

### 상권 코드와 공간 연결

[공식 통계지도](https://www.reb.or.kr/r-one/portal/gis/rcsGisViewerPage.do)의 공개 응답과 통계표 분류 메타데이터를 대조했다. 지도 `regionCd`는 법정동/행정동 코드가 아니며, OpenAPI의 `CLS_ID`와도 다르다. 공식 웹 분류 메타데이터의 `datano`가 OpenAPI `CLS_ID`, `itmId`가 지도 `regionCd`에 대응하는 것을 테헤란로 실제 데이터로 확인했다. 다른 표/분기는 이 대응을 별도 검증한다.

| --- | --- | --- |
| 강남대로 | 61029493 | 520013 |
| 논현역 | 61029497 | 520016 |
| 도산대로 | 61029498 | 520017 |

**같은 테헤란로의 CLS_ID가 오피스 520019, 중대형 520025, 소규모 520021, 집합 520017로 다르다.** 분류 키는 통계표와 함께 관리한다. 한티역은 집합 상가 분류에서 지도 코드 `61029512`, CLS_ID `520018`을 확인했다. 통계상의 상위 “강남” 권역을 강남구로 취급하지 않는다. 지도 메뉴의 서울 `sidoCd`는 `01`, 도형의 서울 `sidocode`는 `11`이므로 이 둘도 구분한다.

공식 지도 `getCommercialWFS.do`에서 서울 82개 MultiPolygon을 받았으며 모두 geometry 유효성 검사를 통과했다. **도형 속성 `year`는 2024**이고, `gid`, `sidocode`, `sidoname`, `cname`은 있으나 통계표/건물유형별 적용기간과 `regionCd`는 없다. 서울 전체에서 동일 `cname` 중복도 있어 전국 이름만으로 조인할 수 없다.

강남구 법정동 경계와 양의 면적으로 겹친 것은 위 8개와 한티역·양재역·양재말죽거리 등 **11개 도형**이다. 이것은 공간 교차 결과이며 11개가 모두 최신 통계 코드와 연결됐다는 뜻은 아니다. 양재 두 도형의 최신 통계 분류 대응은 미확인이다. 강남대로처럼 구 경계를 넘는 상권의 조사 평균을 “강남구 부분 평균”으로 재계산하지 않는다.

현재 증거로는 “연결 자료가 전혀 없다”도 “2026년 후보 좌표에 사용 가능하다”도 단정할 수 없다. 다음을 모두 검증한 연결만 활성화한다.

1. 통계표·건물유형·분기별 코드 ↔ 지도 상권 코드 대응.
2. 도형의 지역·정확한 이름·버전 ↔ 상권 코드 대응의 유일성.
3. 2024 도형이 해당 조사 분기에 적용되는지와 수집·저장 이용조건.
4. 후보 좌표를 포함하는 유효 도형이 하나인지. 대표점에서 가까운 것으로 대체하지 않음.

미확인이면 `survey_rent_per_m2`·`survey_vacancy`는 NULL과 결측 사유를 반환한다. 기존 검증 좌표 대치 `(127.063642,37.494612)`, 학여울 `(127.070594,37.496663)`, 한티 `(127.052873,37.496237)`는 이번 2024 도형 모두에 **포함되지 않았다**. 이 결과를 근접 테헤란로/한티역 통계로 채우지 않는다.

## 승인 후 구현 순서와 파일

1. **명세 확정**: `docs/planning/data-sources.md` §2.9·2.10과 RPC 메타데이터 계약에 실제 컬럼·단위·코드·결측 정책을 반영한다. `location-simulator.md`의 모든 거래에 층이 있다는 표현을 수정하고 AGENTS.md의 PR 상태를 갱신한다. 계획/기획 문서 변경은 코드와 별도 커밋이다.
2. **소스 수집**: `ingest/commercial_trades.py`, `ingest/rent_survey.py`, `ingest/legal_boundaries.py`. 기존 `RawStore`, DuckDB, psycopg와 페이지 캐시 방식을 재사용한다. PublicDataReader의 해당 메서드는 XML 전 필드·공란·취소를 보존하는지 실제 응답과 비교하고 호환되지 않으면 직접 요청한다. 신규 런타임 라이브러리 추가는 현재 계획에 없다.
3. **원본 보존·집계**: `ingest/sql/commercial_trade_stats.sql`, `ingest/rent_database.py`. 원본 거래·법정동/상권 경계·분류 대응표·분기 조사 자료를 R2에 게시하고 DuckDB로 재읽어 집계한다. 거래는 원문 및 수집월/페이지/행 순서·수집시점으로 출처를 추적한다. 월별 중앙값의 중앙값을 사용하지 않는다.
4. **신규 마이그레이션**: `supabase migration new commercial_rent`로 생성한다. 기존 마이그레이션을 수정하지 않는다. `legal_dongs`, `commercial_trade_stats`, `rent_survey`, 검증된 상권 경계/코드 연결과 private 스냅샷 메타데이터를 만든다. 읽기 RLS·쓰기 권한·공간 인덱스·집계 유일성·단위/값 제약을 포함한다. 개별 거래 테이블은 만들지 않는다.
5. **조회**: `ingest/sql/rent_inputs.sql`, `ingest/verify_rent.py`. 법정동·정확한 층 통계와 조사 상권/건물유형별 자료를 조회한다. 층 표본이 없으면 해당 층 값은 NULL이며 전체층 중앙값으로 몰래 대체하지 않는다. 전체층 통계는 별도 근거로만 제공한다. 건물유형을 하나로 결정할 근거가 없으면 임대료 단일값을 임의 선택하지 않는다. 최종 scalar 필드 통합은 후속 `score_inputs` 태스크에서 명시한다.
6. **운영·검증 문서**: `.env.example`에 `RONE_API_KEY` 및 소스 URL 설정을 추가하고 `docs/development.md`, `docs/data-attribution.md`, `docs/validation/pr6-rent-YYYYMMDD.md`를 갱신한다. 수동 엑셀을 쓰면 다운로드 날짜·분기·원문 파일 해시·갱신 방법을 명시한다.

### 집계·갱신 설계의 승인 제안

- 기존 `commercial_trade_stats(lawd_cd,dong,floor,period_start,period_end,...)`에 **건물유형/면적 기준 식별**을 추가하여 일반·집합의 서로 다른 가격 분모를 섞지 않는 안을 제안한다. 둘 다 원본과 유형별 동·층 집계에 남긴다. 면적 정의가 불명확한 집계는 활성화하지 않는다.
- 취소 제외 외에 **지분 거래·금액/면적 미상 또는 0 이하·단위 해석 불가**를 단가 집계에서 제외하고 사유별 건수를 기록한다. 정상 양수 고가 거래를 임의 이상치로 제거하지 않는다. 같은 공개 필드의 별개 거래를 임의 중복 제거하지 않는다.
- `aggregation_level=all_floors|floor` 등으로 전체층 행과 층별 행을 구분한다. 원천 층 미상 거래는 전체층 집계에 포함하되 `unknown_floor_count`를 함께 기록하고 가짜 층 그룹을 만들지 않는다. 키·CHECK로 `floor=NULL`의 의미와 중복 방지를 명시한다.
- 초기 원본은 기존 계약의 `raw/commercial_trades/{계약월}.parquet`를 따른다. 지연신고/취소 정정 시 다른 바이트로 덮어쓰지 않도록 **버전 경로와 스냅샷 manifest**를 추가하는 안을 제안한다. 예: `raw/commercial_trades/revisions/{조회일시}/{계약월}.parquet`. 이 범위에서만 `ingest/common.py`의 원본 게시 경로 지원을 확장하고 저장소 테스트를 추가한다. 매번 24개월 전체를 다시 집계하여 오래된 취소도 반영한다. DB는 검증 완료 스냅샷을 트랜잭션으로 교체하며 실패 시 기존 집계를 유지한다.

위 제안은 2026-09-20 사용자가 승인했다. 아래 추가 승인 조건이 앞선 초안보다 우선한다.

## 주요 리스크와 중단 조건

- 면적 정의/지분 해석이 확인되지 않으면 단가 계산을 활성화하지 않는다. 문서상 건물명 지오코딩 가정은 실제 응답과 충돌하므로 먼저 명세를 수정한다.
- R-ONE 인증키 또는 공식 엑셀이 필요하다. 무키 5행을 전체 자료로 적재하지 않는다. 통계표 메타데이터의 종료연도가 2024로 남아 있지만 2026Q2 실제 값이 반환됐으므로 메타 종료연도만으로 최신 분기를 판단하지 않는다.
- 지도 응답은 문서화된 OpenAPI와 별도의 웹 서비스다. 코드 연결이 일부 확인돼도 경계의 분기 유효성·이용조건이 확인되기 전에는 후보지 자료로 사용하지 않는다. 미연결은 계획대로 NULL이다.
- 상권은 행정구·법정동을 가로지를 수 있으며 같은 이름/다른 유형/다른 분기 코드를 혼합하면 잘못된 임대료가 된다. 정확한 코드 대응과 시점 검증을 조회 활성화 조건으로 둔다.
- 거래 API에 고유 거래 ID가 없고 동일 공개 필드 행이 존재한다. 행수는 공개 레코드 수이며 독립된 점포 수나 식별 가능한 고유 거래 수로 표현하지 않는다.

원응답 증거는 `.local/validation/pr6/`의 `trades-*-p1.xml`, `trade-census.json`, `molit-doc.*`, `legal-dongs.geojson`, `rone-cls-*-names.json`, `rone-teheran-*.json`, `rone-seoul-boundaries.json`, `boundary-intersections.json`이다. 인증키는 파일·보고서에 기록하지 않았다. 이 계획의 집계 수치/컬럼 관측과 승인 제안을 구분하여 후속 검증 문서로 옮긴다.

## 2026-09-20 추가 승인 조건 (앞선 초안보다 우선)

- 임대동향은 포함 상권→실제 자치구→NULL이며 `rent_level`은 district/gu/NULL이다. 대치동 3곳의 gu 실값은 원천 확보 후 검증한다. R-ONE 조사표에서 강남구를 찾지 못했으며 강남 권역은 서초구를 포함하므로 대체하지 않는다. 사용자에게 충돌을 보고했고 실거래·법정동 작업을 우선한다.
- 실거래 기본값은 같은 동·층·기간의 일반/집합 중 유효 표본이 많은 유형, 표본 5건 미만이면 NULL. 선택 유형과 표본수를 반환하며 동률은 집합 고정이다. 층 미지정은 전체층, 층 지정은 정확한 층만 쓴다.
- R-ONE 키는 `RONE_API_KEY`; 키 전에는 실거래·법정동부터 진행한다. 이 승인은 API 검증 결과와 구분한다.

## 2026-09-20 최종 승인: 자치구 대신 공식 권역

앞선 gu 요구는 사용자 지시로 폐기했다. 조회 수준은 `district` → `region` → NULL이다. 부동산원 조사개요의 공식 포함 자치구 또는 경계를 확인하고 그 범위에 속하는 후보에만 권역값을 반환한다. 정의가 없으면 NULL이며 대치동 3곳의 gu 실값 조건도 적용하지 않는다.

확인한 [조사개요](https://www.reb.or.kr/reb/cm/cntnts/cntntsView.do?cntntsId=1049&mi=9800), [작성기관 통계정보보고서 46쪽](https://www.kostat.go.kr/boardDownload.es?bid=12030&list_no=434408&seq=1), R-ONE 공식 통계메타에는 강남 권역의 공간 정의가 없었고 공식 지도 `cname=강남`은 0개 도형이었다. 강남구 전체 포함을 추론하지 않는다. 정의 확인 전에는 원천 집계만 보존하고 공간 매핑은 비활성화한다.

조회에서 임대료가 없는 상권은 다음 단계로 내려가되, 임대료가 있고 공실률만 결측이면 같은 단계의 공실률 NULL을 유지한다. 건물유형별 값 중 임의 선호를 만들지 않으며 여러 유형이 가능하면 요청 유형이 없을 때 scalar는 NULL, 유형별 값과 사유를 반환한다.
