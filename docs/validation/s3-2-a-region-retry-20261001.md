## uid 격리·검색 일일 한도

- 실제 익명 uid2개로 candidates3행·comparison1행을 만들었다. 소유자는 후보3개를 읽고, 다른 uid의 조회/수정은0행, 다른 사용자로 삽입은403이었다. comparison도 다른 uid에서 보이지 않았다.
- 기존 공개 주소 큐 행을 두 uid가 관찰했다. request_id는 서로 달랐고 RLS 상태 뷰에서 각각 자신의1행만 보였다. 원천 큐·캐시는 수정하지 않았다.
- 두 번째 uid의 외부 호출 예약100회 허용, 101번째false. 같은 세션으로 실제 Vercel 검색 요청 시429 `daily_limit_reached`, 공급자 호출 전에 종료했다. 첫 uid의 별도 예약은 성공했다. 이는 **쿼터 RPC 예약100회 검증**이며 Juso를100번 호출한 것이 아니다.
- 해당 단계 소요: uid 격리3.034초, 일일 한도9.487초. 검증계정2개를 정리했다.
