### 최초 로컬 복제 정밀도 오류 정정

10/11 임시 캡처 스크립트가 CSV 내보내기 전에 `extra_float_digits=3`을 지정하지 않았다. 원격/로컬 기본값 0 때문에 double 원천의 끝자리 일부가 반올림되어 로컬에 적재됐다. 예: subway:0334의 15시 boarding은 원격 float8 비트 `407609e9bd37a6f5`, 최초 로컬 `407609e9bd37a6f0`이었다. 출처 메타데이터 fingerprint 일치는 행의 부동소수점 비트 일치를 보장하지 않는다.

b의 subway_boardings_golden이 최초 로컬 `25550.999999999996`, 원격 `25551`이어서 동점 백분위 경계가 달라졌다. transit은 81.81701931840821 → 81.8250699839299, total은 +0.0012711577139441488. 나머지 네 후보 총점·모든 신뢰도·순위는 같았다. 처음에 합산 순서 차이로 추정했던 설명은 이 원천 비트 대조로 정정한다.

10/12에는 원격 READ ONLY 단일 snapshot에서 **COPY BINARY**로 18개 public + 5개 private provenance 테이블을 다시 복제하고, 로컬 재내보내기의 바이너리 SHA256을 23개 모두 대조했다(77.131초, 불일치 0). 사용자·후보·비교 테이블은 복제하지 않았다. 이 복제본이 위 정정 로컬값의 근거다. 최초 보고·산출물은 덮어쓰지 않는다. 이후 검증 복제는 binary COPY 또는 `extra_float_digits=3`을 명시하고, binary 값/행 해시까지 대조한다.

월간 원자적 coordinator는 원격의 같은 트랜잭션 안에서 원천을 읽고 분포를 계산하므로 이 임시 CSV 복제 경로를 사용하지 않는다. 이번 오류는 그 원자성 시뮬레이션의 커밋/롤백 증거를 바꾸지 않는다.
