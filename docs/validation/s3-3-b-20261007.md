# S3-3 B — 선택 동기화·모바일 3탭 검증

2026-10-07 · [계획](../planning/s3-3-plan.md) · [PR #32](https://github.com/hanbeulYou/Gilmok/pull/32), Draft / base main. 기준 main은 #31 merge `accae5a`, 최종 구현은 `97cac33`(기능 `b50016e` + 모바일 출처 겹침 보완)이다. 수치 원본은 [JSON](s3-3-b-20261007.json)을 따른다.

## 변경과 경계

- `selectedId` 하나를 매트릭스 머리글·총점·카드·지도 칩·마커가 공유한다. 선택과 근거 열기를 분리하며, 이미 열린 근거는 선택 후보로 바뀐다. 같은 좌표 a/d/e는 원래 위치의 묶음 마커와 층 목록을 유지한다.
- 머리글·탭·칩·마커/층 목록에서 방향키·Home/End, 층 목록 Escape·원래 마커 포커스 복귀를 지원한다. 카드 축 근거를 닫으면 직전 탭과 버튼으로 복귀한다. 반응형 전환으로 조작 요소가 숨겨지면 보이는 탭/선택 머리글로 포커스를 옮긴다.
- 모바일 기본 탭은 매트릭스다. 지도는 첫 진입 때만 생성하며 이후 숨겨 보존한다. 복귀/화면 크기 변경 시 resize하고 컴포넌트 해제 시 정리한다. 후보 삭제 시 현재 표시 순서의 첫 후보를 선택하고, 층 수정·ready 갱신에서는 기존 ID를 유지한다.
- **migration 없음. 기존 DB 객체·데이터 계약·채점 v0.4.0·환경변수·의존성·운영 스위치 변경 없음.** A의 RPC 좌표·권한·Micro SQL 증거는 [A 검증](s3-3-a-20261007.md)을 재사용하며 B에서 새 원격 SQL 성능 측정으로 표현하지 않는다.

## 환경과 실제/고정 응답 구분

로컬 macOS, Node22.22.0, pnpm10.7.1, Supabase CLI2.72.7, PostgreSQL17.6/PostGIS3.3.7, Next15.5.26/MapLibre4.7.1. 기존 공개 데이터와 기준 분포 `20260923T111436Z`를 사용했다. 테스트 계정과 검증용 캐시만 생성·정리하며 기존 후보/비교를 변경하지 않았다.

- `pnpm test:e2e`: 실제 로컬 Auth/RPC/노출 Worker/MapLibre WebGL. 외부 주소 API와 배경 스타일만 고정 fixture. RPC 장애 격리 검사는 지도 RPC 503을 의도적으로 주입한다.
- production build/start: 주소 API fixture, **실제 OpenFreeMap CDN**·실제 로컬 DB/Auth/Worker. 브라우저는 Chromium/SwiftShader, 1440×1000, 모바일375·390×844 및1024px 경계다.
- Realtime: 기존 독립 production React 검증 harness + 실제 Postgres/Auth/Realtime/Worker, uid2개. 타일을 설정하지 않은 harness이며 지도 번들 증거에는 사용하지 않는다. ready 전환은 고유 검증 주소의 캐시 fixture 갱신으로 유도한다. Actions/웹훅 실증을 다시 수행한 것은 아니다.
- Preview: 실제 Juso/Vworld(icn1)·원격 익명 Auth/RPC/Worker·실제 OpenFreeMap. 검증용 uid는 Admin API로 해당 uid만 삭제했다. 키·세션·uid는 증거에 저장하지 않았다.

5후보·지도 idle 이후 가중치100회, input 이벤트부터 두 번의 requestAnimationFrame까지 측정한다. p95는 정렬한100개 중95번째, max는100번째다. max는 기록값이며 판정 기준을 바꾸지 않았다.

## 실제 Realtime 회귀

실제2uid WebSocket 프레임과 RLS를 확인했다. opaque request_id·상태·updated_at만 노출, 상대 uid 이벤트0, pending→ready 화면 갱신과 선택 유지, primary800m만 재조회, Worker 재사용, 역순 이벤트 무시, 연결 중단→복귀, 구독 전 ready 정합화, **실제180초 대기** 후 지연 배지 및 후속 ready 갱신을 포함해17항목 통과했다. RPC 실패·브라우저 오류0이다.

검증용 후보는 total57.9900108117868→61.147905548628906, 신뢰도60→75로 바뀌었다. 첫 실행은 캐시 ready 뒤25초 대기에서 시간 초과했다. 당시 두 uid 격리는 통과했고 HTTP RPC 오류는 없었다. 실패 진단 출력을 추가해 같은 제품 코드로 재시험했으며 전체 통과했다. 초기 시간 초과의 원인은 단정하지 않는다. 이 기록을 원격 Micro의 **2uid+연속5채점 공개 전 합본 시험** 통과로 해석하지 않는다. Small 전환 후 재시험이라는 기존 공개 조건은 유지한다.

## Preview·검사·재현

최종 구현 `97cac33`의 [Preview](https://gilmok-klidlxx9a-vineyard.vercel.app)에서 실제 주소 등록5건→원격 채점→양방향 선택·모바일3탭/출처 비겹침을 28.355초에 확인했다. API 상태·최종 모바일 검사와 검증 uid 정리 성공은 JSON에 기록한다. 원격 DB migration/push 또는 운영 변수 전환은 하지 않았다.

- `pnpm lint`, `pnpm typecheck`, `pnpm test`: 통과(Vitest26파일191개, Python269개).
- `pnpm build`, 기존 등록→채점→슬라이더→저장 E2E 확장: 통과. production+실제 CDN도 통과.
- 최종 코드 CI [run37635114271](https://github.com/hanbeulYou/Gilmok/actions/runs/37635114271): 통과. 추가 DB 회귀243개 포함. 최신 commit 검사는 PR Checks를 따른다.
- Realtime 재현: `node tests/compare/build-browser.mjs` → `.local/compare-browser/dist`를127.0.0.1:4173으로 제공 → `PROOF_REALTIME_ONLY=1 uv run --frozen --with playwright python tests/compare/verify_browser.py`. 로컬 DB만 기본 사용하고 검증 fixture/uid를 finally에서 정리한다.
- 지도 E2E: 공개 스냅샷이 적재된 로컬 Supabase에서 `pnpm test:e2e`. production은 같은 provider fixture 환경의 build/start와 실제 `NEXT_PUBLIC_MAP_STYLE_URL`로 같은 흐름을 실행하며 초기 요청을 비동기 chunk 목록과 대조한다.
