## 승강기 원천과 변경 이유

역삼로 460(PNU 1168010600109120013, 대장 1024123872)의 승용/비상용 승강기는 **0/0대**다. 적재된 표제부(`source_version=2026-09-20`)와 R2 `raw/building_hub_titles/2026-09.parquet`의 `rideUseElvtCnt=0`, `emgenUseElvtCnt=0`이 일치한다. 원천 생성일 `crtnDay=20220813`이며 현재 현장 실측을 대신하지 않는다. 사용자의 “승강기 없음” 진술과 모순되지 않는다. b·c의 승용 승강기는 각각 1대다.

기존 “1층 0”은 임대 비용을 건물 축에 섞은 오류였다. 비용은 rent 축이 담당한다. 승강기와 층은 결합해 평가하고, R1+R5 가점 상한 +30으로 상한 100에 층 차이가 흡수되는 현상을 줄였다. 시작점은 60이다. Y는 사용자 승인 **모델 가정**이며 실측 주목도나 학원 매출에 회귀한 계수가 아니다. X는 비교용 대안으로만 기록하며 실행 코드에는 추가하지 않았다.

승용승강기 NULL은 0대로 대체하지 않는다. 1·2층·지하는 양 열이 같아 표대로 적용하고 승강기 관련 신뢰도 차감은 없다. 3층 이상만 통합표 보정 0·신뢰도 −5·“승강기 미확인(대장 값 없음)”을 남긴다. 대장 pending/processing은 기존 60·−15를 유지한다. 다른 독립 신뢰도 감점은 유지한다.

지하 노출은 **입구 간판 높이 2.0m**를 가정한다. 음수 목표 높이로 광선을 쏘지 않으며 Y=0.8(“내려다봐야 보임” 가정)을 적용하고 “지하: 입구 간판 기준 노출”을 표시한다. building R7−25는 그대로다. RPC/scene 계약은 0.2.2를 유지하고 순수 레이캐스트의 지하 목표 높이만 변경했다.

## 저장 호환성과 제한

DB 변경 금지 범위에 따라 비교/명명 가중치 저장 RPC·테이블의 `preset_version=0.3`은 유지한다. 해당 레코드는 계산된 ScoreResult가 아니라 후보 입력과 8축 가중치를 저장한다. 클라이언트는 이 기존 입력 계약을 읽어 **현재 v0.4.0으로 재계산**한다. 화면 버전은 ScoreResult의 0.4.0이다. DB 메타데이터가 새 모델 버전을 기록한다고 주장하지 않으며 과거 모델 점수의 영구 재현 저장소로 사용하지 않는다. 오래된 v0.3 오프라인 ScoreResult 캐시는 거부한다.
