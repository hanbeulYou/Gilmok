## 1. 확정된 과거 실패 기록

## 2. 문서 PR 경로 필터

- `pull_request`에서 변경 경로 전체가 `docs/**` 또는 루트·하위의 `.md`/`.mdx`이면 E2E snapshot 적재·Chromium 설치·E2E/성능 테스트만 건너뛴다. lint/typecheck/test/build, 로컬 DB 시작/test:db/정리는 계속 실행한다.
- checkout `fetch-depth: 0` 후 PR base SHA→검증 HEAD의 전체 Git diff를 읽는다. `--no-renames -z`로 삭제와 이름 변경 전후 경로를 모두 포함하고 공백·개행 파일명도 분리한다. 코드/설정 혼합, 빈 diff·SHA/조회 실패는 E2E를 실행한다. main push는 문서 변경이어도 전체 검증한다.
- workflow 전체의 `paths-ignore`를 사용하지 않아 기존 필수 check 이름을 유지한다. [GitHub 경로 필터 문서](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#onpushpull_requestpull_request_targetpathspaths-ignore)의 workflow 생략 시 Pending 및 파일 diff 제한과 분리한 step 조건이다. 새 라이브러리/권한/Secret 없음.
- 실제 #33 diff(`8abef05`→`6ff6ba9`, 계획 문서 1개)에 실행한 출력: `skip (documentation-only PR); changed paths=1`, `run_e2e=false`.
- 회귀 검사: docs/Markdown 혼합은 skip, app·package/lock·workflow·migration 혼합은 run, main/빈 diff는 run. 301개 문서 추가와 코드→문서 rename을 포함한 임시 Git 저장소의 303개 경로를 전부 읽고 run으로 판정했다.

## 3. 슬라이더 측정·판정

`tests/e2e/slider-performance.ts`의 순수 집계와 브라우저 측정을 E2E·기존 standalone production 검증이 공유한다.

- 5후보, demand 가중치 순서 `i % 41`, 각 100회×3세트. input부터 두 번의 rAF까지 측정하고 nearest-rank p95(index94), max(index99)를 기록한다. 세트마다 지도 idle을 기다리며 원래 가중치·점수·열 순서를 복원한다.
- CI는 세트 p95의 중앙값≤100ms, production은 **모든 세트 각각 p95≤100ms**. 정책 미지정은 엄격한 production이고 잘못된 정책명·불완전/비유한 샘플은 거부한다. 테스트 retries=0.
- 각 세트의 실제 점수 변경/복원·드래그 중 열 순서를 확인한다. 3세트 전체에서 RPC/Worker 추가 호출0을 기존 검사와 함께 검증한다. 이어 demand17 프리셋/비교 저장→같은 uid 재열기를 확인한다.
- 각 세트 100개 원시 시간·p95/max·중앙값·전체 max·판정을 로그 및 Playwright JSON attachment에 남긴다. CI `e2e-proof` artifact는 실패 결과도 포함해 14일 보존한다. 측정 수집 후 임계값을 판정하며 느린 세트를 버리지 않는다.
- 집계 회귀: p95=50/126/66 합성 입력은 CI 통과·production 실패, 두 세트>100은 CI 실패, 100 경계 포함, nearest-rank·원본 보존·누락/NaN 거부 확인. 합성 입력은 과거 실행의 재판정이 아니다.

## 5. 실행 방법·검사 결과

```sh
# 기존 로컬 Supabase를 사용하는 E2E; 원격 DB 대상이 아님
SLIDER_PERFORMANCE_POLICY=ci pnpm test:e2e
E2E_APP_MODE=production SLIDER_PERFORMANCE_POLICY=production pnpm test:e2e
```

- `pnpm lint`, `pnpm typecheck`, `pnpm test`: 통과(Vitest28파일196개, Python269개).
- `pnpm build`: production E2E의 Next build/start 단계에서 통과.
- 두 E2E 실행 통과, standalone production 검증 번들 빌드 통과. 기존 3분 Realtime 합본 시험은 이번 P0에서 재실행하지 않았다.
- `.github/workflows/ci.yml`은 PR에서 위 코드 변경을 감지하여 E2E 전체 실행 대상이다. GitHub runner의 신규 실측·run 링크는 PR 설명과 Actions artifact에 기록한다. 위 로컬 CI 정책 결과를 GitHub runner 실측으로 표현하지 않는다.
- 공개 전 운영 체크리스트에 **내장 GPU 일반 노트북 FPS 확인**을 추가했다. P0는 FPS 통과를 주장하지 않는다.
