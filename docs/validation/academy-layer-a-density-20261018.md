## 자료·측정 방식

사용자 승인으로 학교 보완까지 반영된 **로컬** `gilmok_academy_transition_school_20261016`을 repeatable-read/read-only로 조회했다. 학원·교습소 25,527행, 좌표 25,380행, provider는 전부 juso(미확보 포함)다. 기존 기본 postgres DB의 카카오/Vworld 좌표를 사용하지 않았다. 원격 원천 DB/R2 조회·쓰기 없음. 원격 migration dry-run만 별도 허용 범위로 실행했다.

현재 RPC와 같은 개원 조건·geography ST_DWithin, 동일한 공개 기관명·원문 분야·명시층·보류 필드·좌표 정밀도로 **정상 ready 응답 전체**를 SQL JSONB::text/UTF-8로 직렬화했다. gzip은 `gzip.compress(mtime=0)` 오프라인 크기이며 실제 HTTP 압축 측정이 아니다. 101행 검토 목록에서 학원 99행을 조인하고 학교 2행은 점에서 제외했다. 이름/점 목록을 문서나 GitHub에 게시하지 않고 건수·byte·해시만 보관한다.

G의 학원 표시 revision은 `20261016T032916Z`, 검토 버전 `20261014-v3`다. G release를 별도 로컬 복제본에 게시한 뒤 실제 `academy_layer` RPC의 20개 응답을 대조했고, 아래 예상 raw 바이트와 **20/20 정확히 일치**했다. 본래 학교 보완 DB에는 새 gate를 쓰지 않았다. 좌표 소수점/키/분야 원문을 바꾸지 않았다.

## 70% 문턱과 포맷 절감 판단

1.5MiB는 1,572,864B, 70%는 1,101,004.8B다. a~e 최대는 b/1000m **635,425B(40.40%)**. 800m 최상위 셀은 **592,484B(37.67%)**다.

상위 건수 셀 외에 긴 이름이 많은 셀도 점검하기 위해 보수적인 전 셀 상한을 계산했다. 전체 개원 유좌표 기관 각각을 모두 보류=true/사유/검토 버전 포함으로 직렬화했을 때 최대 점 크기는 **466B**다. 모든 분야·모든 count=25,527로 키운 envelope는 1,205B였고 8,192B 여유를 잡았다. 최대 1,577개 × (466+구분자 2) + 8,192 = **746,228B(47.44%)**여서 10,127셀 전체의 800m도 70%를 넘을 수 없다(현재 원천·계약 기준).

따라서 이번 자료에는 절감안 제시/적용 조건이 발생하지 않았다. 짧은 키·사유 코드화·좌표 6자리·분야 코드 테이블 등 계약 변경을 적용하지 않는다. 실제 변경은 추후 예산 초과와 사용자 승인 후다. 이 결론은 현재 원천의 공간 집합/응답 크기에 대한 것이며 원격 Micro p95 또는 향후 기관 수 증가를 보장하지 않는다.
