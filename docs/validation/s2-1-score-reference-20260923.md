## 재현성과 보존

- R2 입력 20,254행 및 분포 162,032행 게시 후 양방향 EXCEPT ALL 일치. R2에서 내려받은 입력에 동일 TypeScript 함수를 다시 실행한 분포도 **불일치 0**.
- 실제 DB 162,032행을 바이너리 조회해 R2 분포와 키·값을 전수 대조, **불일치 0**. NULL/0 구분을 유지했다.
- 같은 snapshot을 운영 CLI로 재실행한 결과 `already_current`, `changed=false`, 2.132초. 재수집·덮어쓰기 없이 별도 유지보수만 수행했다.
- DB 통합 테스트에서 새 COPY가 제약 오류로 실패해도 이전 값·공개 메타데이터·private manifest가 함께 보존됨을 확인했다. 소스 fingerprint 변경 시 승격 거부, anon/authenticated SELECT 허용 및 DELETE 거부도 확인했다.
- CLI 생성 마이그레이션 2개를 로컬 적용하고 migration list --local로 확인했다. 기존 RPC/원천 테이블 구조와 데이터를 변경하지 않았다. 원격 마이그레이션은 실행하지 않았다.

## 실제 응답으로 확인하고 반영한 항목

1. 기존 score_internal.sources()의 transit_counts는 LIMIT 1로 버스 또는 지하철 원천을 반환한다. 실제 테이블에 두 원천명이 있으므로 배치 manifest는 모든 원천·버전을 기록하고 RPC 메타데이터가 그 검증된 집합에 속하는지 확인한다. 첫 읽기 전용 수집은 불일치에서 중단했고 새 전체 수집으로 검증했다.
2. 로컬 extra_float_digits=0의 텍스트 조회는 소수를 반올림한다. 최초 텍스트 비교는 67,025개 값에서 미세 차이를 보였으나 바이너리 조회에서 모두 일치했다. 저장 손상이 아닌 출력 정밀도 차이이며 COPY 정밀도 회귀 테스트를 추가했다. S2-2의 reference 로딩에서도 정밀도를 보존해야 한다. HTTP 경로의 정밀도는 아직 검증하지 않았다.
3. 실제 전수 모집단·결측 비율·실행 시간·용량은 위 표 및 아래 기록으로 확정했다. 포화 지표 추가 및 R6 판정 규칙은 **사용자 결정**이며 API 검증 결과로 표현하지 않는다. R6 gross_area는 DB 표제부에 있으나 RPC v1.2에는 없고 S2-2에서 추가한다.
