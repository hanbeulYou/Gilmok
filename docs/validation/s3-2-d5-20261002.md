## 실패 경로에서 발견한 재호출

failed 상태의 score_inputs가 상태 투영 시각을 갱신하고, 새 시각의 failed 알림이 다시 score_inputs를 호출했다. 실증에서 반복 800m 호출을 관찰했다. 처음 pending/processing→failed 전환은 한 번 갱신하되, 이미 failed인 같은 요청의 시각 변경만으로는 재채점하지 않도록 수정했다. 실제 processing을 거친 재시도 실패는 다시 한 번 갱신한다. 회귀 테스트는 두 경우를 구분한다.

다음 실증을 위해 워커의 비공개 error_code에 고정 allowlist의 단계별 코드를 저장한다. 오류 원문·응답·URL·키는 저장하지 않는다. 새 진단 코드의 실제 Actions 응답은 이 PR 머지 후에 확인할 수 있다. 기존 두 run의 원인을 새 코드로 소급 확정하지 않는다.
