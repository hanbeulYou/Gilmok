# S3-1 로컬 구현·원격 실행 승인 자료

2026-09-26 · **원격 DB 쓰기 승인 대기**. 프리셋 v0.3·ScoreResult·exposure 0.2.2는 변경하지 않았다. S3-2 결정 세 가지는 문서에만 반영했다.

## 승인 대상

최종 `supabase migration list --local`, `migration list --linked`, `db push --linked --dry-run`은 모두 exit 0이다. 로컬은 **29개 적용**, 원격은 **0개 적용 / 29개 대기**다. 기존 28개에 `20260926093918_s3_foundation_auth.sql` 한 파일을 추가한다. 최종 dry-run 실행은 0.350초였으며 실제 SQL 적용을 수행하거나 성공을 보장하는 검사는 아니다. [CLI 원문](s3-1-dry-run.txt)

복원 대상은 [고정 manifest](s3-1-restore-manifest.json)의 **55개 R2 객체, 1,609,467,137 bytes**다. 원본 51개와 보완 4개이며 아래 SHA256으로 고정했다.

```text
f5b48dd9d6a79bc91b91bfddb2b9a086f900edbb703924754990132c3a1a32ba
```

이 manifest는 로컬 복원·RPC 검증 보고서에 기록된 SHA256과 일치한다. 원격 실행은 이 파일과 검토한 마이그레이션을 사용하며, 실행 직전 이력을 다시 확인한다. 원격 DB 적재·Auth PATCH·Vault·웹훅·실제 pending 요청은 아직 실행하지 않았다.

## 복원 증거

원본 Parquet를 SHA256으로 확인하고 기존 정규화/loader를 재사용했다. 로컬 `gilmok_s3_replay_verified` 별도 DB에 마이그레이션을 적용하여 복원했고, 원래 로컬 DB를 덮어쓰지 않았다. **18개 테이블의 전체 행·도형·메타데이터 digest가 원래 DB와 일치**한다. 기준 분포 162,032행과 source fingerprint도 보존했다. 같은 manifest로 재실행하여 18개 테이블 일치를 다시 확인했고, 쓰기 없이 already_restored로 종료했다. 일반 주소 캐시, auth, 후보/비교, 개인 임대료, private 주소 큐/대장 캐시는 이관하지 않는다. 공개 시설 geocode 스냅샷의 주소는 두 원본 데이터셋에 실제 있는 주소로 제한했다.

생활인구는 원본 재집계와 기존 값 사이 최대 절대 차이 `5.4569682106375694e-11`을 관측했다. 기존 S1 검증 허용오차(abs 1e-8, rel 1e-10)로 모든 키·날짜·sample_days·값·NULL을 대조한 후 기존 값의 비트 표현을 보존했다. 임대동향의 Parquet DECIMAL은 float 변환 없이 읽도록 했다.

건물 좌표 재변환에서는 1,112개 정점의 마지막 비트 차이를 관측했다. 모든 건물 ID·도형 유형·정점 수·정점 경로가 일치하고, 정점별 geography 거리 함수 출력은 모두 0m(함수의 출력 정밀도 내)였다. 1μm보다 큰 차이는 거절하도록 검사한 후 기존 EWKB를 보존했다. 도형·수치의 추정/축소나 채점 조정은 하지 않았다.

## 6조합 RPC 대조

2층, 3회 예열 후 조합당 EXPLAIN ANALYZE 30회, nearest-rank p95다. 아래는 복원한 로컬 별도 DB 결과다. [전체 측정 JSON](s3-1-local-rpc.json)

| 좌표 | 반경 | DB p95(ms) | 기준 응답 대조 |
| --- | ---: | ---: | --- |
| 대치 37.494612,127.063642 | 500m | 19.790 | 통과 |
| 대치 | 1,000m | 71.071 | 통과 |
| 학여울 37.496663,127.070594 | 500m | 14.360 | 통과 |
| 학여울 | 1,000m | 43.884 | 통과 |
| 한티 37.496237,127.052873 | 500m | 30.219 | 통과 |
| 한티 | 1,000m | 91.385 | 통과 |

시각·실행 시간 외에 현행 RPC의 `meta.sources.transit_counts.source` 한 필드만 비교 시 정규화했다. 기존 `sources()`가 버스/지하철 중 LIMIT 1을 반환하여 물리적 행 순서에 따라 값이 달라지기 때문이다. 허용값은 실제 검증한 두 source에 한정하고 모든 다른 필드·집계값은 그대로 대조했다. RPC 자체나 채점 코드는 바꾸지 않았다. 이 예외를 숨기거나 실제 응답을 동일한 JSON 문자열이라고 보고하지 않는다.

별도 DB에는 HTTP 서버가 없어 이 검증의 HTTP 시간은 미측정이다. 원격 실행 후 동일 6조합의 DB·HTTP 대조가 필요하다. 로컬 앱 HTTP 검증은 아래와 같이 별도로 수행했다.

## 인증·앱 검증

- 로컬 GoTrue HTTP로 두 익명 사용자를 만들고 후보/비교의 본인 접근·다른 uid 접근 차단을 확인했다.
- 로컬 Mailpit의 실제 이메일 확인 링크를 완료하고 토큰을 갱신한 뒤, 같은 uid와 기존 후보/비교가 유지되는 것을 확인했다. 이 결과는 DB의 is_anonymous 필드만 바꾼 모의 검증이 아니다. [Auth JSON](s3-1-local-auth.json)
- Chrome 개발 모드에서 `/compare` 최초 익명 로그인 1회·score_inputs 1회, 새로고침 후 같은 uid 재사용을 확인했다. [브라우저 JSON](s3-1-local-browser.json)
- 큐의 신규 10건/11번째 거절, 병렬 요청, 중복 upsert, 캐시 조회, done→pending 재요청, 한국 날짜 경계, 무세션 우회 차단을 DB 테스트로 확인했다.
- `pnpm lint`, `pnpm typecheck`, `pnpm build` 통과. `.next/types` 없는 상태의 typecheck도 통과했다. TypeScript 단위 테스트 86개, Python 단위 테스트 242개, DB 통합 테스트 156개 통과.
