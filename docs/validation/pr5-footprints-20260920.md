# PR 5 footprint 사전 검증 — 2026-09-20

이 기록은 계획을 위한 원본/응답 검사다. 생산 DB 적재·R2 게시·PR 5 구현 완료를 뜻하지 않는다.

## 사용자 제공 ZIP과 읽기 방식

- 파일: `.local/downloads/AL_D010_11_20260909.zip`. 사용자가 제공했으며 **서울 전체분**이다. 서울 원천 DBF 헤더 행 수는 **695,754**, 강남구는 원천 `A23='11680'`으로 추출했다.
- 실제 ZIP 크기 **135,736,236 byte**. SHA-256 `c58c2955ea75d81ba35c369cc1132bd58f9dfd2b56bff09b0796d9335997617a`.
- ZIP 내부 `.shp/.shx/.dbf/.prj/.fix` 5개 파일을 확인했다. 압축 해제 파일을 만들지 않았으며 DuckDB `ST_Read('/vsizip/…')`, Python `ZipFile.open/read`로 직접 읽었다.
- `.prj`의 `AUTHORITY["EPSG","5186"]`와 실제 드라이버 geometry 타입 `GEOMETRY('EPSG:5186')`가 일치한다. GRS80, 중심경선 127°, 원점위도 38°, false easting 200,000m, false northing 600,000m다.
- `.cpg`가 없고 DBF language driver는 0이다. 원문 한글 바이트는 UTF-8이 아니며 **CP949로 강남구 문자열 전체를 엄격하게 해석했다**. 이 DuckDB/GDAL 환경에서 CP949 open option은 Unicode 오류를 해결하지 못했다. ISO-8859-1을 바이트 보존용으로 사용한 뒤 Python에서 CP949로 변환했으며 오류 무시/문자 치환을 하지 않았다.
- 원천은 Polygon이다. EPSG:4326 변환에는 `always_xy=true`를 명시했다. 변환 bbox는 `(127.01335648, 37.45930096)~(127.12406616, 37.53433886)`으로 확인했다.
- 파일명 배포 기준일은 2026-09-09, 강남구 모든 행의 `A22`는 2026-09-06이다. `A28` 생성변경일은 2011-02-07~2026-09-05로 별도 보존한다. 이를 전부 2026년에 새로 측량한 자료라고 표현하지 않는다.

## 강남구 전체 범위 비교

강남구 전체 범위 조회까지 완료했다. SHP는 `A23=11680`, WFS는 강남구 경계와 SHP 도형 범위를 포함하는 bbox를 분할 조회한 뒤 `col_adm_se=11680`으로 골랐다. OSM은 기존 강남구 행정동 경계 합집합 안에 도형 내부 대표점이 있는 건물을 셌다. 관할 속성과 공간 판정은 경계에서 차이가 있으므로 동일 판정이라고 표현하지 않는다.

| 소스 | 강남구 원천 도형/행 | 일반·산 PNU로 API 변환 가능 | 양수 원천 높이 | 양수 지상층수 |
|---|---:|---:|---:|---:|
| GIS건물통합정보 SHP | 28,228 | 28,228 (100%) | 16,653 (58.99%) | 22,241 (78.79%) |
| Vworld WFS | 33,345 | 33,343 (99.994%) | 16,655 (49.95%) | 27,122 (81.34%) |
| OSM | 17,263 | 직접 PNU 태그 0 | 2,044 (11.84%) | 3,410 (19.75%) |

WFS는 말단 영역 178개, 전체 237개 요청으로 응답 잘림 없이 읽고 중첩 영역의 feature ID를 중복 제거했다. 전체 bbox의 고유 73,141개가 첫 요청의 numberMatched=73,141과 일치한 뒤 강남구를 골랐다. SHP의 고유 GIS ID **28,227개가 WFS에 모두 존재**하며 WFS에만 있는 일반 GIS ID 2개와 `ufid=NN` 5,115개가 추가된다. NN 5,115개는 PNU·건물관리번호를 모두 보유하고 4,879개는 양수 층수가 있지만 높이·대장 PK는 없다. 나머지 추가 2개는 토지구분이 `6`인 PNU로, API 일반/산 변환을 하지 않고 미확정 사유를 남긴다. PNU 보유율과 실제 표제부 연결률을 구분한다.

SHP와 WFS에는 각각 원천 ID만 다른 동일 도형·업무 속성 1쌍이 있다. 원문 보존 후 정규화 시 1건으로 처리하는 안이다. WFS의 유효하지 않은 geometry는 1건이며 승인 후 수리 전후 검증한다. OSM은 way 17,237개·relation 26개이고, relation에 속한 way를 중복으로 세지 않았음을 확인했다. 강남구 경계로 동일하게 공간 판정하면 SHP 28,202행, WFS 33,316개다. 숫자를 서울 전체 건물 수나 건물 정답 대비 재현율로 해석하지 않는다. [전수 비교·품질 증거](../validation/pr5-footprints-20260920.md)를 따른다.

전수 비교 자료는 `.local/validation/pr5/full/`의 `report.json`, `validation.json`, `wfs-extra-detail.json`, `pnu-quality.json`, WFS 영역별 JSON과 OSM 응답이다. WFS 관할 PNU 고유 개수는 23,292개다. WFS 중복 쌍은 feature ID와 `sgg_oid=35201/35202`만 다르고 나머지 속성/geometry가 같다. GIS ID 28,227개 포함 여부는 직접 ZIP 읽기 결과와 전수 집합 대조했다.

OSM 응답의 도형 조립 실패 relation 8824257은 송파구 롯데월드타워이며 bbox가 강남구 경계와 교차하지 않아 강남구 집계에는 영향을 주지 않는다. 강남구 집계에서 way/relation ID 중복과 relation member way 중복은 0개다. 숫자 태그에 양수 높이/층수를 가진 경우만 확보로 셌으며 공간·주소 추정으로 PNU를 생성하지 않았다.

## 대장·층별개요 연결

- 표본 PNU 74개를 검사해 정상 응답 72개, 표제부가 있는 PNU 62개·표제부 180행을 확보했다. 정상 0건은 PNU 10개이며, `1168010600110160005`, `1168010600110190000`은 HTTP 503이다.
- 원천 대장 PK와 건축HUB PK를 그대로 비교하면 일치 0건이다. [건축HUB 활용가이드의 PK 전환 규칙과 시군구 코드표](https://www.data.go.kr/data/15134735/openapi.do)를 내려받아 ZIP 안 PDF를 메모리에서 읽었다. **22자리 신규 PK는 그대로, 구 일련번호는 강남구 통합분류코드 `1024` + 실대장 구분 `1` + 일련번호**로 변환한다. 폐말소대장 구분 `0`을 섞지 않는다.
- 공식 규칙 적용 후 같은 PNU 안에서 SHP **70/103 (67.96%)**, WFS **70/129 (54.26%)**가 표제부 PK까지 정확히 연결됐다. PK 미보유·조회 실패·불일치는 구분해 남긴다. PNU가 같다는 이유만으로 단지의 여러 동을 하나의 표제부에 연결하지 않는다.
- 한 필지의 표제부 1행↔층별개요 12행, 아파트 필지의 표제부 44행↔층별개요 507행을 확인했다. 층별개요는 모두 현행 표제부 PK로 연결됐다.
- 요청 `numOfRows=1000`은 실제 100으로 제한됐다. 아파트 507행은 6페이지를 읽어 대조했다. 층 구분·번호·원문 이름·용도·면적·본관/부속을 보존한다.

## 운영과 이용조건

**수동 다운로드 후 R2 raw/에 게시, 갱신 주기 분기.** 로그인 다운로드를 자동 갱신 작업으로 표현하지 않는다. 사용자가 ZIP을 제공하면 배치가 검사·Parquet 변환·게시를 수행하며, 파일 기준일·원본 해시·PRJ·공식 컬럼 정의서를 함께 보존한다. 새 파일이 없으면 기존 source_version을 유지한다. 이번 계획 조사에서는 R2에 게시하지 않았다.

주 소스는 **Vworld WFS**를 추천한다. 강남구 전수 대조에서 SHP의 고유 GIS ID 28,227개가 모두 포함됐고, 추가 NN 도형 5,115개 중 4,879개에 층수가 있었다. 추가 도형의 대장 PK는 없으므로 미연결 상태를 보존한다. SHP는 분기 대조·대체 원본으로 유지한다. 도로명주소 도형은 SHP·WFS·OSM이 모두 부족할 때만 신청을 제안한다.

- [SHP 배포 화면](https://www.vworld.kr/dtmk/dtmk_ntads_s002.do?svcCde=NA&dsId=18)은 CC BY를 표시하지만 연결 라이선스 URL은 BY-NC-ND여서 표기 불일치가 있다. 파일 안에는 별도 라이선스 문서가 없다. 상업 제공·가공·재배포 조건 확정은 게시 전 확인 항목이다.
- [WFS 데이터 명세](https://www.data.go.kr/catalog/15123970/openapi.json)의 이용허락 표시와 [Vworld 서비스 약관](https://www.vworld.kr/v4po_prcint_a001.do)의 영리 이용·정보 복제/제공 조건은 별도로 확인한다. 인증 성공만으로 서비스 이용 범위를 확정하지 않는다.
- [OSM ODbL](https://www.openstreetmap.org/copyright)은 출처·라이선스 표시와 공개 파생 DB 공유 조건을 따른다.

원본 ZIP은 `.local/downloads/`, 분석 JSON·네트워크 원문·비교용 Parquet·스크립트 로그는 `.local/validation/pr5/`에 있다. 키 값이나 키가 포함된 요청 URL은 기록하지 않았다. 생산 스키마·RPC·적재 코드는 아직 구현하지 않았다.

## 사용자 최종 결정 (실측과 구분)

2026-09-20 사용자는 SHP를 주 소스, WFS를 SHP에 없는 도형의 보조로 승인했다. 이전 WFS 추천은 대체됐다. 근거는 SHP의 PNU 100%·대장 연결률 우위·CC BY 배포 조건·주 원본의 API 약관/쿼터 비의존이다. 포털 링크 불일치 관측 이력 자체를 삭제하거나 사용자 결정을 새 API 검증으로 표현하지 않는다. WFS 보조는 대장 집계에서 제외하지만 표시/차폐에는 포함한다. 높이·unknown 규칙과 수리/원본 보존은 승인된 PR 5 계획을 따른다.
