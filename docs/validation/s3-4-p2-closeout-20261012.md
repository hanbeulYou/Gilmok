## D5 측정 환경·방법

측정 시작 직전 **19:34:58 KST**, 종료 **19:42:52 KST**에 `pmset -g batt`, `pmset -g custom`, CoreGraphics/NSScreen 주사율을 읽었다. 두 시점 모두 **AC Power·충전 100%·AC powermode 0·LG HDR 4K 60Hz**였다. 배터리 프로필의 powermode 1은 현재 AC 프로필이 아니다. OS 설정은 에이전트가 변경하지 않았고, 측정 종료를 사용자에게 알렸다.

- MacBook Pro M5 Pro, 실제 `ANGLE Metal Renderer: Apple M5 Pro`, Chrome 154.0.0.0, macOS 26.5.2 (25F84), SwiftShader 미사용.
- CSS viewport 1440×1000, DPR 2. 지도 canvas CSS 598×550 / 실제 1196×1100.
- 주 화면 LG: 논리 1920×1080, scale 2, 60Hz. 내장 화면은 120Hz였지만 사용하지 않았다. 측정 Chrome 창의 OS bounds는 x22/y30/1442×1050으로 LG 화면 안에 있었다. 10초 간격 관측 47건에서 AC·60Hz를 유지했고, 측정 PID가 존재하는 모든 관측에서 창이 LG 안에 있음을 확인했다. 다른 사용자 Chrome 창은 증거에서 제외했다.
- 로컬 **production build/start**, 실제 로컬 Supabase·Worker·OpenFreeMap·MapLibre/deck.gl. 선택 a의 오버레이 활성 상태에서 108 샘플·차폐 건물을 함께 렌더했다.

실제 GPU/production 정책으로 상태마다 100회×3세트를 측정했다. CI 중앙값 완화 정책을 적용하지 않고 **모든 세트 p95≤100ms**를 확인했다.

최신 main 병합은 프론트·Worker·패키지 코드를 바꾸지 않았다. 기존 브라우저 리소스 기준 번들 실측은 그대로 유효하다: 초기 JS 241,386B gzip(#32 대비 +3,843B≤5KiB), 건물+overlay 추가 JS 201,830B≤500KiB, CSS 538B≤10KiB. 이번 build에서도 overlay 세 chunk gzip 합 **198,639B**를 재확인했다. 별도 정적 route manifest의 JS는 202,017B이며 동적 초기 리소스까지 포함하는 위 예산 값과 혼용하지 않는다.
