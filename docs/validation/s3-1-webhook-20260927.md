# S3-1 머지 후 웹훅 실증 — 2026-09-27

**S3-1 완료 보류.** 익명 세션의 실제 주소 1건은 pending으로 생성됐지만 GitHub dispatch가 HTTP 403으로 거절됐다. Actions run은 생성되지 않아 run URL이 없으며 캐시 ready·RPC ready 재조회는 미실행이다. 종료 처리에서 Repository variable을 false, DB 트리거를 disabled로 복귀하고 테스트 Auth 사용자를 삭제했다. pending 행은 보존했고 외부 대장 워커는 실행하지 않았다.

## 실제 pending 1건과 실패 지점

공개 학원 주소 원본에서 지오코딩이 확인된 **서울특별시 강남구 역삼로 452**를 사용했다. 좌표 `(37.5022026747964, 127.056660127756)`, 반경 800m, 3층. 이 좌표를 포함하는 적재 건물 도형이 없고 주소 대장 캐시에도 없어 `score_inputs`의 주소 fallback을 사용한다. 캐시를 비우거나 허위 좌표를 만들지 않았다.

GitHub 응답: `Resource not accessible by personal access token`. 응답 헤더 `x-accepted-github-permissions: contents=write`. Vault의 `gilmok_github_dispatch_token`은 `.env`의 값과 일치하므로 다른 토큰이 저장된 문제는 아니다. 값은 출력·기록하지 않았다. [오류·복귀 상태](s3-1-webhook-error-20260927.json).

재개 조건은 해당 fine-grained PAT에 `hanbeulYou/Gilmok` 저장소 **Contents: Read and write** 권한을 부여하거나, 그 권한을 가진 토큰으로 `.env`를 갱신하는 것이다. 새 토큰이면 Vault도 같은 승인 범위에서 갱신해야 한다. 현재 pending 1건을 별도 검토 없이 추가 생성·초기화하거나, CLI의 다른 토큰으로 dispatch를 우회하지 않았다. 실제 webhook→Actions 경로가 통과해야 완료다.

## Vercel 실제 변수 이름·배포 확인

사용자는 `/compare` JSON 확인과 Auth URL 등록 완료를 알려줬다. 조회된 실제 상태는 아래와 달라 완료 증거로 합치지 않는다.

- Vercel API에서 `vineyard / gilmok`, 도메인 `gilmok-hazel.vercel.app`을 확인했다.
- 프로젝트 환경변수 API(`decrypt=false`)로 **25개 이름**과 Production/Preview 적용 범위를 확인했다. 값은 복호화·출력·보관하지 않았다.
- 배포 목록 API는 빈 배열, 프로젝트 production target 없음. `https://gilmok-hazel.vercel.app/compare`는 **HTTP 404**였다. 사용자가 JSON을 확인한 정확한 URL 확인이 필요하다.
- 현재 연결된 원격 Supabase: `site_url=http://localhost:3000`, `uri_allow_list=""`, anonymous 활성화는 true. [Auth URL 조회](s3-1-auth-url-20260927.json).
