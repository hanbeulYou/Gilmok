# PR 3 지하철·버스 실데이터 검증 — 2026-09-19

사용자 승인: 서울 전체 교통, 2026-06~08 평균, 6월 선검증, 승하차량 조인율 90% 미만 사전 보고, 신분당선 대체 추정 제외. PR 2 GitHub #4 머지 기준 브랜치에서 작업했다. 아래 수치는 실제 응답·R2·로컬 DB 측정이며 사용자 결정을 검증 결과로 대신 쓰지 않는다.

## 단위와 중복 증거

원천 시간대 값은 월 합계다. 6월 일별 30일 자료를 역·노선 또는 내부 정류장 ID로 합산하고 월 시간대 합계와 승차·하차를 각각 비교했다.

| subway | 18,512 | 621 | 220,839,027 | 219,762,585 | 0 |
| bus100 | 3,660 | 123 | 558,545 | 546,289 | 0 |

버스 100번의 이름 변경 구간과 5511번의 같은 정류장 반복 정차(순번)를 포함한다. 별도 차원의 행은 합산하고 동일한 모든 컬럼의 복제 행만 제거한다. 7월 지하철 1,242행 중 621행이 완전 복제였고 621개 관측만 집계했다. 같은 차원인데 값이 다른 경우는 자동 합산하지 않고 실패한다. 환승역의 서로 다른 노선 관측은 유지하며 유일 이용자 수나 환승객 수로 해석하지 않는다.

7월 복제 문제는 추가로 일별 31일 자료와 대조했다. 승차 218,556,908·하차 217,413,424로 복제 제거 후 월 시간대 합계와 일치했다. 원래 역명 그대로 비교하면 `숙대입구(갈월)`→`숙대입구(서울시교육청)` 부기 변경 때문에 두 이름으로 나뉘지만, 이미 채택한 같은 노선 안의 괄호 부기 제거 규칙을 적용하면 역별 불일치도 0이다. 별도 노선 병합이나 추가 추정은 없다. 상세는 `.local/validation/pr3/july-subway-proof.json`에 있다.

3개월 합계÷92일로 시간대별 일평균을 만든다. 어느 한 월의 필요한 값이 없으면 그 평균은 NULL이다. 월별 일평균의 단순 평균·평일/주말 추정·신분당선 대체는 없다.

## 위치와 적재

- 위치 조회일: 2026-09-19. 6~8월 위치·개폐 이력의 일치 여부는 미검증이다.

## 대치동 교통 SQL 검증

좌표는 위치 API의 대치·학여울·한티 역이며, 각각 행정동 경계의 대치동 포함을 DB에서 확인했다. 반경 500m·1km, 준비 호출 3회 후 조합별 30회. DB 시간은 `EXPLAIN (ANALYZE, FORMAT JSON)`의 Execution Time, p95는 정렬한 30개 중 ceil(30×0.95)번째다. DB 왕복은 Python 단조 시계로 별도 측정했다. 최근접 지하철은 반경 밖도 최대 2km, 골든타임은 [15,22), 승차+하차 일평균 합이다.

## 호환성·검사·남은 항목

- PublicDataReader 실제 일별 호출: 616행을 반환했지만 구 컬럼명 때문에 6개 데이터 컬럼이 모두 빈 문자열. 표준 HTTP 라이브러리 어댑터를 사용했고 새 의존성은 추가하지 않았다.

- 단위·중복·월 누락·NULL/0·방향/반복 정차·조인율 90% 경계, DB 원자 실패 보존·읽기 전용 RLS·500m/1km/2km 및 골든타임 경계를 검증했다.
- `pnpm lint`, `pnpm typecheck`, `pnpm test`(Vitest 1·Python 68), `pnpm test:db`(49) 통과. 총 118개 검사다.
- 다음: 상가 서울 전체 적재 계획. 전체 RPC, 월별 스케줄, Kakao 403 해결, NEIS·원격 Supabase 인증은 이번 PR 완료로 표시하지 않는다.
