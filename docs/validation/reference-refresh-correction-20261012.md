## a~e 원정밀도 검증

좌표·층은 바이너리 복제 검증 fixture와 동일, v0.4.0, 반경 800m(학교 1000m), 실제 exposure 엔진/Worker, 임대료 미입력. 독립적으로 계산·보존한 로컬 재생성 결과를 기대값으로 사용했다. 원격 응답을 로컬 기대값으로 덮어쓰지 않았다.

파생 demand·flow raw에는 최대 약 2.42e-8의 말단 차이가 남지만 정규화 점수·총점에는 차이가 없다. 개별 raw 값과 차이는 JSON에 보존한다. 이 잔차의 세부 원인은 이번에 확정하지 않았으며, 모든 파생 raw의 비트까지 동일하다는 결과로 해석하지 않는다. 향후 비교 정책 안정화에서 별도로 다룬다.

## 앞으로의 로컬·원격 대조 기준

- 먼저 원천/좌표/반경/층/모델/preset/reference snapshot을 일치시킨다. 원천 복제는 binary COPY 또는 원정밀도 CSV(efd=3) 후 바이너리 해시 검산을 요구한다. 메타데이터 fingerprint만으로 원천 비트 일치를 주장하지 않는다.
- **총점은 반올림·허용오차 없는 Number 정확 동등성**을 통과 기준으로 한다. 같은 JS 순수 함수 경로에서 정규화 8축 점수도 정확 비교하고, NULL·순위·신뢰도·사유 코드는 정확 일치를 요구한다. 총점이 다르면 차이를 기록하고 Ready로 바꾸지 않는다.
- 화면의 소수 2자리 일치는 추가 표시 검사다. 총점 원정밀도 실패를 대신 통과시키는 기준이 아니다. 이전 두 자리 예외 승인은 첫 복구 이력에만 해당한다.
- 파생 raw는 원정밀도 차이를 지표별 기록하여 동점 변화 여부를 확인한다. 원천 비트 검산과 파생 값의 연산 결과 대조를 구분한다.
- Q6 비교 키·합산 순서 고정은 후속 PR 제안이다. 채택 시 SQL/TS·분포/후보 양쪽의 정책을 명시하고 경계/전수 영향 검산 후 승인받는다. 이전의 “총점 소수 6자리 대조” 제안은 현재 완료 기준으로 채택하지 않으며, 위 원정밀도 기준을 완화하려면 별도 결정이 필요하다.
