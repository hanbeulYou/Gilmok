# PR 7 score_inputs 통합·S1 완료 검증

> 이 문서는 v1.0 최초 검증 이력이다. 현재 v1.2 계약·수정 후 수치는 [전 층 추가 검증](pr7-building-all-floors-20260922.md)을 따른다. 링크된 예시·요약 JSON은 최신 v1.2로 갱신됐다.

검증일: 2026-09-21. 측정 시작 UTC: `2026-09-21T06:12:22.597946+00:00`. 승인 계획 및 사용자 추가 요구(전체 JSON 스키마, 묶음별 ms, 한 묶음 결측 시 격리)를 구현했다. **S1 완료 기준 통과.** 임대동향 공간 연결은 PR 6의 승인된 비활성 상태를 유지한다.

## 기존 상태와 변경

재개 시 `supabase migration list --local`로 `20260920124903`, `20260920125502`가 적용되어 있음을 확인했다. 적용된 마이그레이션은 수정하지 않았다. 새로운 원천 적재·삭제·VACUUM·원격 DB 전환은 하지 않았다.

통합 RPC는 공통 좌표/도형과 출처를 준비하고 묶음별 한 행 집계를 수행한 뒤 JSON을 결합한다. 기존 반경 SQL을 실행 경로에 이어 붙이지 않았다. `rent_inputs`는 동일 내부 함수를 공유하는 호환 wrapper로 유지하고, `buildings_in_radius`는 별도 지도/차폐 RPC로 유지했다. 도형 목록을 만들었다가 통합 입력에서 버리지 않는다.

## 완료 기준 측정

고정 좌표: 대치 `(lng=127.063642, lat=37.494612)`, 학여울 `(127.070594,37.496663)`, 한티 `(127.052873,37.496237)`. 모두 요청 층 2이며 좌표를 건물 안으로 옮기지 않았다.

조합별 준비 호출 3회 후 **DB EXPLAIN 30회**, 총 180회. DB p95는 `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)`의 Execution Time, nearest-rank 방식(정렬 30개 중 29번째)이다. 준비된 캐시 조건이며 cold 성능이라고 표현하지 않는다. 6개 조합을 섞어 하나의 p95로 판정하지 않았다.

## 내부 실행계획과 독립 대조

Supabase 로컬 DB가 `LOAD 'auto_explain'`을 거부했다. 따라서 저장된 SQL 함수의 `pg_proc.prosrc`를 직접 읽어 인자 식별자만 바인딩하고 EXPLAIN ANALYZE했다. 문자열 리터럴/컬럼명은 보존한다. 추출 SQL 결과가 실제 RPC 해당 묶음과 같은지도 확인했다. rent의 기존 PL/pgSQL에서는 법정동/매매/조사 집계의 세 SQL 문장을 추출해 대조했다. 출처 helper는 비공개 테이블 접근 권한을 가진 관리 연결에서 별도 EXPLAIN했다.

- demand/flow/transit/market/compete/building은 내부 최종 Actual Rows=1. rent의 각 집계도 한 행이며 최종 JSON 조합에서 원천 간 다대다 조인이 없다.
- 411,512행 생활인구·554,092행 상가 등 대형 조회 경로에서 불필요한 Seq Scan 없음. 공간 GiST 선필터와 생활인구 PK 조회를 확인했다. 건물 footprint와 대장·요청 층은 후보 필터 뒤 조회한다.
- 작은 매매 집계 180행·조사 집계 34행의 Seq Scan은 허용했다. source helper의 LIMIT 1 조회는 실제 1행을 읽고 멈추며 전체 대형 테이블 집계와 구분했다. 작은 출처/분기 집계 전체 읽기도 기록했다.
- 저장한 모든 내부 계획에서 Temp Written Blocks=0, 디스크 spill 없음. Actual Rows/Loops와 인덱스·필터 수치를 함께 보존했다.
- 상가·학원·학교·교통은 기존 독립 검증 SQL과, 매매·임대는 기존 rent_inputs와, unknown 비율은 buildings_in_radius와 대조했다.
- 인구·생활인구는 공간 선필터를 생략한 독립 면적 교차 SQL과 대조했다. 합성 데이터에서는 비NULL 시간대·7시간 평균·연령대 비율을 별도로 검증했다.

전체 6조합의 JSON 실행계획·30회 개별 측정값·응답은 `.local/validation/pr7/20260921-final/report.json`에 있다. 재생성 명령은 `uv run --frozen python -m ingest.verify_score_inputs --directory .local/validation/pr7/20260921-final`이다. 공개 요약은 [summary JSON](pr7-score-inputs-summary.json), 실제 응답은 [example JSON](pr7-score-inputs-example.json)이다.

## 결측과 건물 양수 값 검증

- 대치 500m는 교차 격자 21개 모두 행이 있지만 시간별 total 유효 격자는 17~20개다. 완전 집계 정책으로 flow가 NULL이어도 학교 2개·상가 822개·학원 207개·2층 집합 매매 표본 11건을 반환한다. 각 시간의 기대/유효 격자 수를 meta.flow_coverage에 남겼다.
- 실제 임대 공간 매핑은 비활성이므로 6조합 모두 rent_level/임대료/공실률 NULL이다. 구 통계·근접 상권·과거 분기로 대체하지 않았다.
- 한티 고정 좌표의 법정동은 도곡동이며 2층 집합 매매 표본 1건은 단가 NULL이다.
- 대치/한티 후보 도형은 대장 미연결 WFS 보조이며 unknown 높이를 4m 실제 높이로 반환하지 않는다. 학여울 좌표는 후보 건물 미매칭으로 사유와 NULL을 반환한다.
- 별도 실제 건물 검증점 `(lng=127.020937983636, lat=37.5246562306353)`은 `shp:0000201804824469406000000000`에 유일하게 매칭됐다. 높이 19.2m, 지상 4층, 2층 용도 2행(1,788㎡/9.92㎡), 승강기 승용/비상용 각각 0을 원천과 대조했다. 0은 결측이 아니다. 이 보완점은 6조합 성능 판정에 섞지 않았다.

## 테스트와 S1 인계

- `pnpm lint`, `pnpm typecheck`, `pnpm test`: 통과. Vitest 1건, Python 단위 테스트 195건.
- `pnpm test:db`: 112건 통과. 21개 통합 RPC 테스트는 기존 실데이터 밖의 합성 영역에서 수행하고 롤백한다.
- demand/flow/transit/market/compete/building/rent를 각각 결측으로 만든 7개 테스트에서 다른 6개 묶음 값 유지. 다중 상가/학교/학원 및 복수 층 용도에서도 교차 집계 증폭 없음.
- NULL과 0, 시간 결측 시 7시간 평균 NULL, 층/지하층 구분, 복수 건물의 모호한 매칭, unknown 비율, 최소 표본 규칙, 잘못된 입력 거부, 기존 rent RPC 결과 보존을 확인했다.
- anon/authenticated 읽기 결과 동일, 기존 쓰기/비공개 메타데이터 직접 조회 차단 유지. 사용자 개인 데이터 테이블은 통합 함수에서 조회하지 않는다. 기존 후보지 RLS 테스트도 통과했다.
- 확정된 전체 JSON 타입·단위·NULL·추정 플래그·시간 계측 의미와 실제 응답을 [data-sources.md 3절](../planning/data-sources.md#3-score_inputs--s2-채점-입력-계약-v12)에 기록했다.

이번 문서 수정의 근거는 **기존 실제 적재 데이터에 대한 통합 RPC 응답**이다. 외부 원천 API를 새로 호출하거나 미확인 임대 공간 정의를 확인했다고 표현하지 않는다. 부분 관측·생활인구 완전 집계 결측·임대 공간 비활성은 S2에 인계하는 데이터 한계다. 다음 태스크는 S2 채점 명세 확정과 별도 서울 전체 건축물 적재 계획이며 채점/UI는 구현하지 않았다.
