# PR 2 생활인구 고정 컬럼·유효 날짜 평균 실측

2026-09-19, 사용자 승인에 따라 JSONB를 제외하고 고정 컬럼으로 전환했다. 최초 표본의 예상 용량이 500MB 미만임을 보고한 뒤 로컬 Supabase에 전체 적재했다. 이어 승인된 연령대별 유효 날짜 평균과 합계÷일수 방식까지 반영해 다시 적재·측정했다. 원격 Supabase와 외부 인증 API는 호출하지 않았다.

## 확정한 저장·집계 계약

- 공간·시간 키: `(resolution_m, cell_id, dow_type, hour)`, 250m·평일/주말·00~23시 유지.
- 인구 컬럼: `total`, `age_0_4`, `age_5_9`, `age_10_14`, `age_15_19`, `age_20_29`, `age_30_39`, `age_40_49`, `age_50_59`, `age_60_plus`. 모두 nullable double precision, 비음수·유한값만 허용한다.
- `sample_days smallint` 하나만 표본 수로 저장한다. 이는 total(SPOP)의 모든 관측 행정동 조각이 유효한 날짜 수이며 연령대별 분모가 아니다.
- 날짜×셀×시간별로 남녀·원천 연령 밴드·행정동 조각을 먼저 합산한다. 어떤 조각이든 비공개이면 그 날짜 전체를 해당 연령대 평균에서 제외한다. 연령대마다 자기 유효 일수로 나누며, 유효 일수가 0일 때만 NULL이다.
- `total`은 기존 완전기간 검증을 유지한다. 기간의 해당 요일 유형에 누락·비공개 날짜가 있으면 NULL이며, 완전할 때 SPOP 합계÷유효 일수다. 원천 SPOP를 연령대 합계로 대체하지 않는다.
- 0~4·5~9세는 원본이 0~9세만 제공하므로 두 컬럼 모두 NULL이다. 15~19세는 그대로 보존해 학원 채점의 생활인구 입력에 사용한다. 주민등록에서 직접 합산한 `demand.pop_15_18`과 섞거나 원본 15~19세를 비례 분할하지 않는다.
- `period_start`, `period_end`, `source`, `source_version`, `ingested_at`, `estimated`를 보존한다. 관측치 집계와 반경 면적 비례 추정은 구분하며 반경 배분 시 estimated=true를 반환한다.
- `*`(3명 이하)를 제외해 평균이 높아질 수 있는 편향을 사용자 승인으로 허용하며 `data-sources.md`에 명시했다. 이를 반경 전체 오차가 3명 이하라는 보장으로 확대하지 않는다.

## 날짜별 임시 파일: 평균 저장 금지

DuckDB `memory_limit=1GB`, `threads=2`, `temp_directory`를 지정한 전체 날짜 중간 테이블은 실제 3개월 원본에서 메모리 부족이 발생했다. 설정한 메모리 안에서 완료되도록 첫 집계를 하루 단위로 제한했다.

임시 Parquet의 한 행은 날짜×셀×시간이다. 원본에서 제공되는 각 밴드에 대해 `<band>_sum`, `<band>_days`를 저장한다. 유효 날짜는 셀의 모든 조각 합계와 일수 1, 비공개 날짜는 합계 0과 일수 0이다. 이 0은 중간 누산용이며 최종 결측 인구를 0으로 저장하는 것이 아니다. 전체 결측 컬럼은 `NULLIF(SUM(days),0)`으로 NULL이 된다.

최종 계산은 **SUM(컬럼별 합계) / SUM(컬럼별 유효 일수)**다. 월·파일별 평균의 평균을 계산하지 않는다. 연령별 분모는 집계 중간 단계에서만 사용하고 최종 DB에는 요청한 sample_days 하나만 둔다. 임시 파일은 검증·최종 Parquet 교체가 끝나면 제거하며 원본 Parquet는 수정하지 않는다.

회귀 테스트 예: 전체 인구가 6월 한 날짜 10명, 7월 두 날짜 100·200명이면 310/3명이다. 같은 기간에 10~14세는 두 날짜만 유효하면 해당 두 값의 합÷2, 15~19세가 한 날짜만 유효하면 그 값÷1을 사용한다. total 기준 sample_days=3을 모든 연령대의 분모로 쓰지 않는다.

## 예상 용량: 구현 전 조건 확인

실제 기존 집계를 고정 컬럼으로 펼친 100,000행을 로컬 PostgreSQL 17.6 임시 테이블에 COPY했다. 출처·기간·추정 플래그·PK 인덱스를 포함하여 ANALYZE 후 `pg_total_relation_size`를 측정했다. 해시순 표본이며 측정 트랜잭션은 rollback했다.

| 항목 | byte | MB (10진) |
| --- | ---: | ---: |
| 실제 표본 100,000행 | 24,141,824 | 24.14 |
| 전체 411,512행 환산 | 99,346,503 | 99.35 |
| 모든 인구 컬럼을 비NULL로 채운 보수적 표본의 전체 환산 | 117,381,922 | 117.38 |
| 표본 측정 시 기존 로컬 DB | 22,178,963 | 22.18 |

이 단계는 연령대 평균을 유효 날짜만 사용하는 후속 결정 전의 표본이다. 해당 결정으로 NULL이 줄어도 모든 컬럼 비NULL 표본의 용량 범위 안에 든다. 500MB 조건을 충족해 구현을 진행했고, 2시간 단위 축소 및 주말 골든타임만 저장하는 대안은 적용하지 않았다.

## 최종 전체 적재 실측

기준 기간은 **2026-06-01~08-31**, 원본 23,344,369행/관측 셀 8,598개다. 출처·다운로드 폼·해시는 [최초 조사 기록](pr2-population-20260919.md)을 따른다.

| 항목 | 실측 |
| --- | ---: |
| 최종 생활인구 행 수 | 411,512 |
| 최종 관측 셀 수 | 8,598 |
| 최종 집계 Parquet | 12,115,328 byte |
| sample_days 범위 | 0~66 |
| 재적재 후 living_pop 할당 공간(이전 스냅샷 공간 포함) | 186,580,992 byte |

| 위 값 중 PK 인덱스 | 20,488,192 byte |
| 정리 후 DB 전체 | **121,416,851 byte (121.42MB)** |

커밋 직전 DB 크기도 209,194,131 byte로 확인했다. 이는 관측 시점의 크기이며 작업 중 최대 디스크 사용량을 연속 측정한 값은 아니다. 로컬에서 이 테이블만 VACUUM FULL해 새 구조의 보관 크기도 따로 측정했다. 삭제·재삽입은 이전 행 공간을 남기므로 정상 운영의 재적재 비용을 정리 후 크기만으로 평가하지 않는다.

현재 로컬 DB에는 아직 모든 S1 소스가 적재된 것은 아니다. 따라서 이 결과는 **생활인구와 현재 로컬 DB가 500MB 이내**임을 확인한 것이며 S1 전체 최종 용량이나 Supabase 원격 프로젝트의 사용량을 보장하지 않는다.

## 마이그레이션·검증·남은 범위

`20260919111139_living_population_fixed.sql`로 새 고정 컬럼 테이블을 추가했다. 최초 마이그레이션을 로컬에 적용한 뒤 사용자가 유효 날짜 평균을 결정했으므로 기존 파일을 수정하지 않고 `20260919111751_living_population_valid_age_days.sql`에서 설명을 갱신했다. 기존 격자·집계구 데이터는 보존했다. PK는 격자 공간 조회 이후 셀별 프로필 탐색에 사용하고 격자 FK는 기존 경계 스냅샷 교체가 가능한 deferred 제약으로 둔다.

적재는 임시 테이블→공통 기간·표본 수 검증→원자적 스냅샷 교체→FK 검증→성공 감사 기록 순서다. 빈 입력·중복·음수·NaN/무한대·잘못된 시간/요일·기간 불일치·미등록 셀은 기존 데이터와 감사 기록을 보존한 채 실패한다. API 역할은 읽기만 가능하다. 롤백 시 새 조회·적재 경로 사용을 중지할 수 있으며, 원본과 기존 공간 테이블을 삭제하는 축소 작업은 포함하지 않았다.

검증: `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm test:db` 통과. Vitest 1 + Python 단위 39 + DB 통합 33 = **73개**. 실제 3개월 재집계·전체 적재·용량 확인까지 완료했다. `score_inputs`는 아직 구현 전이므로 S1 p95 성능 통과로 표시하지 않는다.

원본과 결과는 로컬 `.local/ingest`에 있다. R2 게시·원격 Supabase 전환은 하지 않았다. 기존 PR 2의 최신 427개 행정동 경계 확보와 주민등록 공간 적재, R2 게시가 남아 있어 PR은 초안으로 유지한다.
