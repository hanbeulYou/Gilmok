## 검증 방법

`ingest.academy_transition`은 loopback DB만 허용하고 요청 전 SQLite claim을 영속화한다. 검색 응답이 정확히 한 주소와 일치할 때만 Juso 좌표를 호출한다. 좌표 호출 간격은0.6초 이상이며 같은 건물 식별자의 응답은 재사용한다. 모호한 응답을 첫 검색 결과로 대체하지 않는다. 좌표는 EPSG:5179 출입구에서 PostGIS로4326 변환하며 PNU는 공식 검색 식별자로 조합한다. 운영 오류/응답 유실은 자동 재호출하지 않고 멈춘다.

공간 검산은 기존 좌표와 새 좌표의 geography 거리, Juso PNU 건물 도형 포함, 서울 경계 포함을 확인한다. 건물이 강남구에만 적재된 점을 고려해 도형 부재와 도형 밖을 구분한다. 도형 밖 좌표는 출입구일 수 있으므로 자동 중심점 보정 없이 검토 목록에 남기며, 로컬 영향 계산은 공급자 좌표 그대로 사용한다.

비교 후보는 기존 a~e와 seed20260926 무작위5셀의 **고정된 채점 좌표**다. 후보 위치·층·800m 프리셋·가중치·v0.4.0 모델·cluster 고정 상수는 유지한다. 학원·학교 좌표와 그에 대응하는 기준분포만 함께 바꾼다. 기존 exposure Worker 순수 함수도 그대로 실행한다.

## 원자성·호환성·롤백

Migration `20261012150926_academy_display_provenance.sql`: **새 private 테이블2개·RLS/권한만 추가, 기존 객체·행 변경 없음**. 격리 로컬 DB에만 적용했다. 원격 dry-run/push를 실행하지 않았다.

층 파생은 정합성 데이터이므로 실패 시 원천/분포와 함께 롤백한다. source/display(P0001)/reference 단계의 강제 실패와 외부 연결 관측 시험을 통해 구 원천·층·분포 유지 및 성공 시 동시 교체를 확인했다. release 행이 없는 상태에서는 기존 월간 동작을 유지하고, G release 이후에는 Juso 실제 공급자·좌표 정책을 검증하며 층 파생도 함께 갱신한다. provider 이름만 juso이고 실제 좌표가 Vworld인 과거 캐시, 실패 Juso 대신 성공 Kakao로 돌아가는 경로를 차단했다.

롤백은 학원·학교·캐시·분포2테이블·place/refresh snapshot·ingest_runs·층 파생2테이블, 총10개를 COPY BINARY로 백업한다. manifest에 행 수, 바이너리/압축파일 SHA256, source fingerprint를 남긴다. 파일 해시를 확인하고 전체를 단일 트랜잭션으로 복원한 뒤 행 수·바이너리 digest·fingerprint가 일치해야 커밋한다. float8 전체 자릿수를 보존하며 sequence를 되감지 않는다. baseline 복원 시험10테이블 일치 통과. 실제 재산출 승격 후 복원은 아래 전수 실행 결과로 갱신한다.
