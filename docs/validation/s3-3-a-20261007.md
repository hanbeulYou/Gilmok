## 1. 구현과 좌표 검산

MapLibre GL JS **4.7.1**을 사용한다. `@types/geojson 7946.0.16`은 RPC GeoJSON의 TypeScript 검사 전용이다. 지도 래퍼·Turf·deck.gl·새 좌표 변환 라이브러리는 추가하지 않았다.

마커는 `ComparisonCandidate.candidate.{lng,lat}`를 그대로 사용한다. RPC에도 같은 lat/lng를 전달하고 응답 center의 정확한 일치를 검사한다. 4326 도형은 화면에서만 MapLibre가 투영한다. 반경은 PostGIS geography `ST_Project`의 원주 128점+폐합점이다. 모든 꼭짓점을 geography `ST_Distance`로 다시 확인했으며 800/1000m 오차는 **0.001m 미만**이다. SQL뿐 아니라 실제 HTTP에서도 center가 원래 double 좌표와 정확히 일치한다.

| 후보 | lng | lat | 묶음 |
|---|---:|---:|---|
| a 역삼로460 3층 / d 4층 / e 1층 | 127.05758573871447 | 37.5025721944737 | 하나의 마커, 1·3·4층 목록 |
| b 도곡로409 2층 | 127.05516718391107 | 37.497368428505624 | 독립 마커 |
| c 역삼로546 3층 | 127.06287290714192 | 37.50428792732002 | 독립 마커 |

실제 등록→채점 RPC 요청 좌표와 DOM 마커 좌표를 대조했다. 후보 5개/좌표 묶음 3개이며 반올림·jitter·주소 재검색이 없다. 같은 좌표에서 층만 바꿀 때 지도 RPC를 다시 호출하지 않는다. ID와 순위는 기존 store를 사용한다. 완성된 매트릭스 열 선택·키보드·모바일 3탭은 다음 B에서 마감하며, A의 모바일 진입은 `지도 보기` 버튼이다.

역은 1.2km 안 지하철 노선별 원천 ID를 보존한다. 학교는 1km 안 초/중/고를 구분한다. 1199.99/1200.01m 역, 999.99/1000.01m 학교를 합성해서 경계를 검증했다. 좌표 없는 학교 7곳은 **원천 전체 결측**으로 표시하며 반경 안 결측 수로 해석하지 않는다. 원천 미적재·서울 밖·반경 안 0건을 구분하고 추정 원천은 `estimated`를 보존한다.

`compare_map_context`는 선택 후보의 초기 채점 종료 후 호출한다. 동시 요청 1개, 동일 좌표+원천 fingerprint의 진행 중 요청 공유 및 메모리 캐시(최대 10개), 대기 중 오래된 선택 건너뛰기, 15초 timeout을 적용했다. fingerprint는 기존 입력의 `admin_boundaries/subway_positions/schools`다. 가중치·층 변경은 지도 데이터 갱신 사유가 아니다. 지도 RPC 503을 주입해도 기존 점수·근거를 유지하며 재시도로 회복했다.

## 2. 지도 RPC 성능 — 로컬 실데이터

직접 SQL `EXPLAIN (ANALYZE, FORMAT JSON)`을 authenticated 역할로 주소별 31회 실행했다. 첫 실행은 **새 연결의 첫 호출**이며, 선행 검증이 끝난 DB의 shared buffers를 비우지 않았다. 엄격한 서버 캐시 콜드 값으로 부르지 않는다. 나머지 30회는 nearest-rank p95다. HTTP는 anon API 키+실제 익명 로그인 access token의 authenticated 경로 1회이며 DB 기준과 섞지 않는다.

| 역삼로460 | 17.462 | 1.431 / 1.541 | 45.070 | 16,564 | 6 / 11 |
| 도곡로409 | 17.360 | 1.489 / 1.523 | 28.778 | 18,000 | 6 / 16 |
| 역삼로546 | 19.414 | 1.489 / 1.534 | 25.913 | 14,492 | 5 / 5 |

## 3. 번들·lazy load·브라우저

### 실제 OpenFreeMap 첫 고정 뷰

새 브라우저에서 a 1개를 등록한 1440×1000 뷰다. 실제 외부 style/TileJSON/sprite/glyph/vector tile을 호출했고 모두 HTTP200이었다. Playwright BrowserContext에서 **MapLibre Worker 요청까지 포함**하여 응답 body+header 전송량을 합산했다. 첫 idle 뒤 진행 중 응답 완료를 최대 1초 더 수집했다.

- 외부 요청 **16개**, **1,644,306 bytes**. 이 중 vector tile 10개, glyph 2개, sprite 2개, style/TileJSON 각 1개다.
- 셸 **1076.6ms**, 첫 map idle **3580.3ms** (셸 이후 **2503.7ms**).
- 지도 앱 번들 예산과 외부 타일/폰트 전송량은 별개다. 해당 시점 뷰/네트워크의 1회 관측이며 CDN이나 향후 데이터 크기의 상한이 아니다.
- 앞선 page 단위 CDP 수집은 Worker 타일 요청이 빠졌으므로 전송량 결론에 쓰지 않았다. 위 수치가 고정 뷰 최종 측정이다.
- 한글 도로명, 역·학교, 800/1000m 원, 3자 출처 링크가 실제 렌더됨을 확인했다. CI에서는 외부 CDN 변동을 피하기 위해 style 응답만 고정하고 실제 MapLibre/WebGL·local RPC를 사용한다.

### Micro 직접 SQL — 콜드/웜 구분

환경은 사용자가 대시보드에서 확정한 **Micro 유지**, PostgreSQL17.6/shared_buffers256MB/work_mem3500kB다. 이 작업에서 compute·statement_timeout·예열 스케줄·DB 재시작을 변경하지 않았다. Session pooler의 직접 SQL 연결에 `SET LOCAL ROLE authenticated`, `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)`을 사용했다. 새 지도 함수의 HTTP 호출 전에 SQL을 먼저 측정했다.

**a의 첫 호출은 배포 후 새 함수의 최초 실행**이다. shared read331개가 관측됐으며, 이를 이 검증의 최초/콜드 관측값으로 분리한다. DB shared buffers·OS cache를 강제로 비우지는 않았다. b/c는 새 연결·각 주소의 첫 호출이지만 a와 공간 원천을 공유하고 read0이므로 완전한 I/O 콜드라고 주장하지 않는다. 각 첫 호출은 warm30회 p95에서 제외했다. p95는 30개 중 nearest-rank29번째다.
