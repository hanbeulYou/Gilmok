# feat: 지하철·버스 3개월 승하차 적재

교통 입력이 없는 상태에서 서울 역·정류장 위치와 2026년 6~8월 시간대 승하차를 조회할 수 있도록 적재한다. 월 합계의 합÷92일로 일평균을 계산해 8월 한 달의 방학 패턴에 치우치지 않게 한다. 신분당선·위치 미매칭·월 결측은 대체 추정하지 않는다.

6월 지하철 전체와 버스 100·5511번의 30일 합계 대조로 단위 및 개명/반복 정차 처리를 검증했다. 환승역의 노선별 관측과 방향별 정류장은 유지하고, 7월 지하철의 완전 복제 621행만 집계에서 제거한다. 원본은 그대로 R2에 보존한다.

7월 지하철도 추가로 일별 31일 합계와 대조했다. 숙대입구의 부기 변경에 기존 정규화 규칙을 적용한 뒤 역·노선별 승차·하차 불일치 0을 확인했다. DB 264,696행의 binary 재읽기와 집계 Parquet도 정확히 일치한다.

서울 위치 11,620개·시간대 집계 264,696행을 로컬 Supabase에 원자 적재했다. R2 8개 객체의 실제 재읽기·재집계가 로컬 기준본과 일치한다. 승하차량 기준 조인율은 지하철 99.71~99.74%, 버스 95.24~95.42%다. 고유 ID·행 기준 비율과 미매칭 목록도 별도로 기록했다.

기존 인구 데이터·마이그레이션은 보존하며 새 `20260919122817_transit.sql`을 CLI로 생성했다. 테이블은 공개 읽기만 허용하고, 조인·결측 메타데이터는 비공개로 보존한다. 새 라이브러리·자동 스케줄·원격 Supabase 전환·전체 RPC는 포함하지 않는다.

검증: `pnpm lint`, `pnpm typecheck`, `pnpm test`(Vitest 1·Python 68), `pnpm test:db`(49) 통과. 대치동 교통 SQL 6개 조합 p95는 0.203~0.340ms다. 이는 전체 RPC 성능 결과가 아니다. 최초 적재 DB 173.65MB, 재적재의 이전 행 공간 포함 224.83MB.

위치 소스는 9월 조회본으로 6~8월 당시 위치·개폐 이력은 미검증이다. 원천 월 자료에서 평일/주말을 추정하지 않으며, 3개월을 충족하지 못한 버스 6개 정류장 144행은 NULL로 유지한다. 원격 Supabase와 계정별 일 쿼터는 미검증이다.

버스 미매칭 4.6543%는 균일하지 않다. 미매칭량의 52.85%/38.61%가 간선/지선이며, 유형 내부 누락률은 서울광역 49.96%, 마을 0.63%다. 군포·성남 등 서울 외 연결 노선과 2xx ID 대역에 편중되고, 서울에서 주로 관측되는 100~124 대역의 잔여 누락에는 홍대입구·합정 가상정류장이 두드러진다. ID 대역을 미확인 좌표의 행정구역으로 확정하지 않는다. [편중 분석](pr3-bus-coverage-20260919.md)에 분모·유형별 수치·노선·한계를 기록했다.

**S2 인계: 교통 축은 요일 구분 없는 일평균, 생활인구는 평일/주말 분리.** 두 시간대 원본의 6~8월 스키마에서 요일 구분이 없음을 확인했고 `data-sources.md`에 명시했다. 채점 시 이 차이와 누락 편중을 고려하되 이번 PR에서 추정·보정하지 않는다.

실측·해시·전체 미매칭 목록 경로: [PR 3 검증 기록](pr3-transit-20260919.md). 재현: [개발 문서](../development.md#pr-3-교통-실데이터-재현).
