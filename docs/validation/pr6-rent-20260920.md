# PR 6 실거래·임대동향 적재 검증

검증일 2026-09-20, 스냅샷 `20260920T120200Z`. 구현 범위는 [승인 계획](../planning/pr6-rent-plan.md)과 최종 사용자 변경인 **상권 → 공식 권역 → NULL**이다. 최초 자치구 폴백 요구는 폐기됐다.

## 실데이터와 저장소

| 대상 | 실제 결과 |

실거래 `buildingAr`는 원천 건물면적(㎡)이다. 일반/집합 모두 면적 기준명을 `building_area`로 유지하고 전용면적이라고 단정하지 않는다. 만원을 원으로 변환하며 24개월 전체 거래에서 중앙값을 계산한다. 공개 필드가 동일한 행도 별개 거래일 수 있어 값만으로 중복 제거하지 않는다. 표본수는 공개 레코드 수이며 고유 점포 수가 아니다.

R2 **27개 객체, 630,899 byte**의 DuckDB 재읽기에서 중복을 포함한 multiset 불일치 **0건**이다. R2 원본에서 다시 만든 매매 집계 180행과 임대동향 집계 34행을 각각 DB 전체와 대조했고 대칭 차집합은 모두 **0행**이었다. 숫자 DECIMAL은 재읽기 과정에서 float64로 바꾸지 않아 원천 정밀도를 유지한다.

- `raw/commercial_trades/2024-09.parquet`~`2026-08.parquet`: 24개.
- `raw/legal_boundaries/2026-09.parquet`: 1개, 원응답 메타데이터와 주변 도형까지 보존.
- `raw/rent_survey/revisions/20260920T120200Z/2026-06.parquet`: 1개, 전국 원응답 1,810행.
- `raw/rent_survey_scope/revisions/20260920T120200Z/2026-06.parquet`: 1개, 공식 분류 메타데이터·원천 상권 도형·교차 검증·연결 사유.

객체별 SHA-256·행수·크기·재읽기 결과는 로컬 `report.json`, `rent-survey-report.json`에 기록했다. 로컬 원본 스냅샷은 `.local/validation/pr6/20260920T120200Z/`이며 비밀이나 개별 거래를 Git에 추가하지 않는다. Supabase에는 개별 거래 테이블이 없다.

## 공식 권역 정의와 NULL 사유

사용자는 구 통계 부재를 확인한 뒤 **자치구 대신 공식 권역으로 폴백하되, 공식 정의가 없으면 NULL**로 변경 승인했다. 다음 공식 자료를 확인했으나 강남 권역의 포함 자치구 또는 경계를 확보하지 못했다.

- [한국부동산원 조사개요](https://www.reb.or.kr/reb/cm/cntnts/cntntsView.do?cntntsId=1049&mi=9800).
- [작성기관 통계정보보고서](https://www.kostat.go.kr/boardDownload.es?bid=12030&list_no=434408&seq=1), 46쪽, 2024-08-20 작성.
- R-ONE 통계메타 `S237220284` 조사개요.
- [공식 통계지도](https://www.reb.or.kr/r-one/portal/gis/rcsGisViewerPage.do)의 `getCommercialWFS.do`, `cname='강남'`: 0개 도형.

통계의 `CLS_ID=510004`, 지도 분류 코드 `61029200`에 ‘강남’ 값이 존재하는 것은 확인했다. 그러나 그 하위 상권에는 서초구 상권도 있어 강남구와 같은 영역이 아니며, 하위 상권 목록만으로 자치구 전역 포함을 추론하지 않는다. 일반적인 GBD 정의나 최근접 상권도 사용하지 않는다.

상권 도형 82개의 원천 속성 `year=2024`는 확인했지만 2026Q2의 유형별 적용 기간을 확정하지 못했다. 따라서 상권 수치도 사실로 보존하되 연결을 활성화하지 않는다. `rent_areas.geom=NULL`, `mapping_verified=false`이며 출처와 결측 사유를 남겼다. 이 상태에서 실제 후보의 `survey_rent_per_m2`, `survey_vacancy`, `rent_level`은 모두 NULL이다. **자료가 없어서 0을 반환한 것이 아니라 공간 적용 근거가 부족한 결측**이다.

조회 계약은 합성 DB fixture에서 포함 상권→포함 권역→NULL, 미검증/중첩 경계, 근접 상권 대체 금지까지 검증했다. 이것을 실권역 좌표 매칭 성공으로 표현하지 않는다.

임대료가 있는 상권은 공실률만 결측이어도 그 단계와 공실률 NULL을 유지한다. 임대료가 없으면 권역 단계로 내려간다. 한 `rent_level`에 다른 단계의 공실률을 섞지 않는다. 건물유형은 섞지 않고 유형별 값을 제공하며 요청 유형이 없는데 여러 유형이 가능하면 scalar는 `building_class_required`와 NULL이다.

## 실제 좌표와 조회 결과

기존 검증 좌표를 변경하지 않았다. 새로 확인한 법정동 경계상 **한티 좌표는 도곡동**이며, 대치·학여울은 대치동이다. 행정동/역 이름을 법정동으로 대체하지 않는다.

| 대치 | 동일 | 동일 | 2 | 집합 | 11 | 23,715,087.702951 |

반경 500m와 1km에서 위 동·층 통계는 동일하다. 각 유형을 분리한 뒤 표본이 많은 유형을 기본값으로 선택하며 동률은 집합 고정이다. 5건 미만이면 단가를 NULL로 반환하되 선택 유형·표본수를 함께 반환한다. 층별 표본이 없으면 전체층으로 대신하지 않는다.

12개 조합(3좌표×2반경×층 미지정/2층), 조합별 워밍업 3회·측정 30회:

- DB `EXPLAIN ANALYZE` 실행 시간 p95 **0.122~0.485ms**, 모두 1,000ms 미만.
- 익명 HTTP 왕복 **1.633~14.214ms**, 각 조합 1회 관측값. HTTP p95라고 표현하지 않는다.
- HTTP JSON과 SQL RPC JSON 전 항목 일치. DB 읽기와 동일하게 anon 조회 가능, 쓰기와 private 적재 메타데이터 조회는 금지.
- 이번 결과는 **`rent_inputs`의 증거**다. 전체 7개 묶음 `score_inputs` 또는 S1 전체 완료를 의미하지 않는다.

## 검사와 수정 증거

- `pnpm lint`, `pnpm typecheck`, `pnpm test` 통과. Vitest 1건, Python 단위 테스트 183건.
- `pnpm test:db` 91건 통과. 마지막 nullable-floor fixture의 pandas 경고는 수정 후 해당 테스트를 다시 통과했다.
- 금액 단위·DECIMAL 보존, 취소/지분·표본 5건·동률, 공개 필드 동일 거래 보존, 페이지 누락·표본 API 응답 거부, 원본 불변·R2 재읽기 다중집합 비교를 검증했다.
- 최신 분기 전체 결측 시 이전 분기로 대체하지 않는다. 같은 출처의 전체 스냅샷 재적재에서 원천에서 삭제된 행을 제거하고 다른 출처는 보존한다.
- 타입·트랜잭션 검증 중 nullable 층이 pandas float가 되어 COPY에서 실패한 문제를 정수 검증 변환으로 수정했다. 해당 실패와 좌표 검증 실패는 트랜잭션 롤백되어 부분 적재되지 않았다.
- RLS·정확한 층 선택·재적재 멱등성과 중간 실패 시 이전 데이터/경계 복원을 DB 테스트로 검증했다.

SQL은 CLI로 생성한 `20260920114642_commercial_rent.sql`, `20260920115702_rent_survey_availability.sql`, `20260920120131_rent_current_snapshot.sql`의 세 신규 마이그레이션으로 적용했다. 기존 스프린트 마이그레이션은 수정하지 않았다.

다음 태스크는 전체 `score_inputs` 통합과 S1 최종 검증이다. 공식 권역 공간 정의·상권 경계 분기 적용을 확보하면 별도 근거 검증 후 공간 연결을 활성화할 수 있다.
